# TCN／Transformer 时序模型升级评估

评估日期：2026-10-10。建议先训练轻量因果 TCN，把小型因果 Transformer 作为同数据、同切分的对照。两者的本机推理开销都具备接入潜力，当前主要缺口是经过人工复核的动作时间段标注，而不是算力。此文以基础人体动作作为首轮范围；装配工序另行定义标签和视觉输入。

## 现有基础与缺口

- `algorithms/tracking.py` 输出同一轨迹的时间序列：17 个关键点、置信度、边界框、规则分数、可靠性；新分析同时保留 `rawKeypoints`。现有 `ActionDecoder` 是规则分数解码器，不是训练模型。
- `backend/streams.py` 已按用户、视频流保存跟踪状态，画面规格和工位变更会重置，可增加逐轨迹模型窗口。`backend/realtime.py` 的推理锁串行处理请求，不能只看单个模型耗时就承诺多路吞吐。
- 已检查 `assets`、`models` 和算法代码，发现姿态/目标/手部模型与示例视频，未找到可直接训练的人工动作标注集。历史 `analysis.json` 的动作标签来自规则，不能作为测试真值。旧结果可能没有原始关键点，需要统一版本重新提取。
- 本机实测 PyTorch 2.8.0+cu128、CUDA 可用、RTX 5070 Ti。这里只评估本机；部署服务器需单独测量。
- 发现报告顶层 `model.temporalModel` 仍写为 `causal-duration-v1`，而逐人解码输出已为v3。接入训练模型时应统一版本来源，并校验顶层元数据与逐帧结果一致，避免实验来源混淆。

## 架构与本机测量

输入原型为 `[batch,64,74]`，输出每个时刻 5 个动作 logits。以下模型均为随机初始化，输入为合成数据，**没有训练或准确率测量**。

| 项目 | 因果 TCN | 因果 Transformer |
|---|---|---|
| 原型结构 | 宽度64，4个残差块，每块2层卷积，核3，膨胀1/2/4/8 | 宽度64，2层，4头，前馈128，因果掩码 |
| 参数量 | 103,941 | 76,165 |
| 上下文 | 感受野61个采样点 | 窗口内最多64个采样点 |
| CPU单轨迹 p50／p95 | 0.660／1.086 ms | 0.269／0.681 ms |
| GPU单轨迹 p50／p95 | 0.548／1.205 ms | 0.530／0.698 ms |
| GPU八轨迹整批 p50／p95 | 0.375／0.933 ms | 0.513／0.831 ms |
| 主要取舍 | 局部时序结构明确，便于约束上下文并做增量缓存 | 更灵活的窗口内关联，需要验证数据量、位置编码与泛化 |

测量使用 CPU 4线程、FP32、10次预热、50次采样，每次GPU同步。耗时只含整窗口前向，不含姿态提取、数据预处理、传输、HTTP、首次加载；未做增量缓存，也不是参数量匹配的严格架构优劣实验。两种模型在改变后半段输入时，前半段输出最大差值均为0，已检查未来信息泄漏。小样本计时会有调度波动，不能据此宣称TCN更快或Transformer更准确。

复现：`node tools/python.cjs tools/benchmark-temporal.py`。结构代码在 `tools/benchmark-temporal.py`，测量记录在 `work/temporal-model-evaluation/benchmark.json`。

## 第一轮标注任务

优先标注 `raised` 抬手、`reaching` 伸手、`bending` 躯干前倾、`walking` 持续位置移动、`standing` 站立/原地作业。标签允许重叠，例如“移动且抬手”；以多标签 sigmoid/BCE 训练，不能强行用互斥 softmax。

`standing` 必须从画面直接确认，不能把其他类别未标注自动填成standing。`unknown` 是不可判断状态，不当作某个具体动作；另标 `unobservable`（遮挡/出画/模糊）和 `transition`（边界不确定），对应训练损失掩码。已审阅且可见、确认没有这五类动作的区间可作为全零负样本。未审阅区间一律不能作负样本。

动作边界以源视频时间为准，保存半开区间 `[start_s,end_s)`。标注者独立看原视频，几何规则只作辅助建议：

| 标签 | 标注对象 | 易混淆负例 |
|---|---|---|
| raised | 手腕明显抬高至肩附近以上的动作/保持段，标左右侧 | 抬头、遮挡导致肩定位漂移 |
| reaching | 手臂向外伸展的动作/保持段，可与抬手重叠 | 仅身体横移、屈肘贴身 |
| bending | 相对本人通常姿态明显前倾的段落 | 相机倾斜、坐姿基线变化 |
| walking | 可观察的持续身体位置移动 | 原地重心摆动、镜头移动 |
| standing | 站立或原地作业且有充分画面依据 | 坐姿、下半身完全不可见 |

先做20–30分钟双人试标，统一上述定义及“起始动作还是到位保持”的边界口径，然后冻结标注指南版本。试验采集目标建议6–10小时源视频、8–12名参与者、至少3个日期、2个机位；这是启动预算，不是充分性保证。按人物可见时长、每类独立动作事件数统计覆盖，建议首轮每类至少200个事件，再依据学习曲线补采。多人同屏时标注工作量按逐人可见时长增加，不能直接等同于源视频长度。

至少20%的标注由第二人独立复核，稀有动作、遮挡、边界争议优先全量复核；记录分歧及裁定。必须包含原地摆动、交叉遮挡、漏检、快速切换、动作共现、空工位等困难样本。优先采集有明确训练使用权限的现场视频；仓库工人演示视频注明来源授权限制，不默认纳入训练。

## 数据格式与防泄漏

示例格式见 `work/temporal-model-evaluation/annotation-example.json`，它是虚构的格式示例，不是已标注数据。每个视频记录：视频ID、SHA256、源时长、会话/日期/机位、匿名人物ID、轨迹映射、审阅区间、动作区间、可观测性、标注者和复核状态。

人物ID是数据集内部的匿名关联ID；自动 `trackId` 不是人物身份。只在人工确认后关联遮挡前后片段；不确定的关联保持分段。身份标注用于独立划分，不作为模型输入。

先划分完整录制会话与人物组，再生成滑动窗口。训练/验证/测试可从约70/15/15开始，但同一人、同源视频、重叠窗口或相邻切片不得跨分区；若人员跨多个会话，用人物—会话关系的连通分组划分。另设未见机位测试。数据不足以形成独立分区时先补采，不能随机按帧凑测试集。

标注使用源时间。分析片段对齐用 `source.start + frame.time`；ROI裁剪关键点需结合 `source.crop` 转回统一坐标。固定姿态提取模型、模型哈希、输入尺寸和特征版本，避免训练/部署不一致。

## 输入与训练设计

- 首轮固定10 Hz因果采样、64点窗口（6.4秒采样槽）；61点TCN感受野覆盖6秒历史跨度。窗口不要求等待填满才输出：左侧补零并显式标记有效性，暖启动覆盖不足时输出unknown。
- 74维候选输入：17关节的身体归一化x/y、置信度、有效掩码共68维，加髋中心图像位移速度2维、框高变化1维、采样年龄1维、身体尺度1维、跟踪可靠性1维。保留图像尺度运动信息，避免身体归一化后丢失walking证据。
- 只用当前与过去观测重采样，不用未来帧线性插值。漏检不补成有效观测；时间间隔过长或关联不确定时重置窗口。低频输入不能靠复制帧伪造证据，训练加入5–30 fps变化与丢帧扰动。
- 第一轮从固定版本的原始关键点提特征；平滑版作为单独消融，避免隐性重复平滑。数据标准化参数只从训练集拟合。
- 基线A为当前规则+v3解码；B为TCN；C为Transformer。使用相同标注、特征、划分与训练预算，每个模型至少3个随机种子。多标签带掩码BCE、训练集类别权重、验证集早停；训练增强包括坐标小噪声、关节丢失、时间缩放，左右翻转需交换关节编号和侧别标注。
- 输出动作证据和可观测性，不直接输出SOP合格。阈值和后处理只用验证集校准；保留当前质量门控，评估额外0.3秒确认是否导致双重延迟。

## 接入边界和验收

建议把特征窗口与模型预测封装为独立 `TemporalPredictor`，由PoseTracker逐轨迹调用。模型状态绑定用户、流、轨迹、配置签名；漏检/超时/歧义沿用现有清理入口。历史规则 `signals` 保留，另加 `modelSignals` 和模型版本；SOP从哪一路取证据必须显式配置，不能静默替换当前帧信号。神经网络历史预测还需当前关键点有效性门控，防止遮挡期间完成步骤。

上线包应包括权重SHA256、标签/特征版本、归一化统计、窗口长度、采样策略、校准阈值、训练划分清单和测试报告。加载失败或版本不兼容回退规则模式并记录原因。先影子运行：同时记录新旧预测，用户侧继续使用现有结果；通过验收后再切换。

建议的预注册验收目标（尚未达到，需在试标后冻结）：

1. 报告每类precision/recall/F1、宏F1和按类事件F1（tIoU 0.1/0.25/0.5）；重叠标签逐类评价。区分可见标签质量与端到端覆盖率，不能只评估成功检测帧。
2. 对稳定段统计错误切换次数/人分钟，对匹配动作事件报告起止偏差、确认延迟p50/p95，同时单列漏报事件；按人物/会话bootstrap置信区间。
3. 首轮建议宏F1较规则提升至少5个百分点、错误切换减少至少20%，关键类别召回下降不超过2个百分点，端到端新增p95延迟不超过150 ms。根据现场要求进一步收紧；单次均值改善不足以发布。
4. 报告遮挡/未见人/未见机位分组、冷启动、5–30 fps、1/8人以及目标并发流数的表现；真实HTTP链路压测含姿态模型与队列/拒绝率。部署硬件另测。
