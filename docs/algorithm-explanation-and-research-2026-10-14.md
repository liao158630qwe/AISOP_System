# AI-SOP 算法详解与优化研究路线

日期：2026-10-14。本文解释当前实现为何这样工作、容易在哪里出错，以及如何把优化做成可验证的研究。

配套资料：[项目模型与算法清单](models-and-algorithms-2026-10-14.md)、[本次训练／验证集诊断](lamp-model-training-diagnostics-2026-10-14.md)。文中“当前实现”依据工作区源码；“建议实验”尚未实现或执行。当前视频系统使用的规则链与研究目录中的神经时序模型需要分别理解。

## 1. 优化研究首先要解决什么

建议将主任务限定为：**在一个固定灯具工位中，识别哪个位置发生了哪次可见操作、区间何时开始结束，并在证据充分时判断漏步或错序。** 首轮从两个代表性位置 A/B 开始，再扩展到八个位置。

研究对象应是带位置和独立尝试编号的事件，而不只是“抬手、站立、弯腰”之类人体姿态。

```text
操作事件 = 产品周期 + 目标位置 + 动作类别 + 独立尝试编号
         + 起止时间 + 证据可判定性 + 发布时间
```

当前最优先的问题有三个：

1. **训练尚未学出有效操作识别。** 本次只读诊断发现，现有三轮合成试训的两个模型在训练集和验证集上都没有正确预测操作采样点；关系模型还没有正确识别任何 A/B 位置采样点。
2. **现场信息尚未形成输入闭环。** 灯具专用工具／尖端检测、真实图像特征、目标配准与人工事件标注未完成，人体关键点不足以独立区分八个螺丝位置。
3. **逐帧预测尚未形成可靠在线事件。** 边界头已经存在，但训练后的事件导出仍按连续操作标签切段，没有使用边界头控制发布和重复尝试分离。

因此应先完成训练诊断与现场可观测性验证，再研究位置关系和时序结构，最后优化推理速度。继续增加集成成员或降低发布门槛，不能解决当前动作与位置尚未学会的问题。

## 2. 从画面到动作：服务端算法如何工作

### 2.1 人体姿态模型提供观测，不直接提供工艺语义

当前可选 RTMO、RTMPose 和 YOLO11-pose，最终统一输出人体框、检测分数和 COCO-17 关键点。底层模型训练来自相应外部框架，项目主要实现推理适配和下游算法。

| 方法 | 基本原理 | 优势 | 工位中容易遇到的限制 |
|---|---|---|---|
| RTMO | 一次前向完成多人人体与姿态估计 | 无需逐人再跑姿态网络，适合多人实时观测 | 小人物、遮挡及工具接触细节仍需现场评测 |
| RTMPose + YOLOX | 先检测人体，再对人体区域估计关键点；RTMPose 使用坐标分类表示 | 人体裁切后可集中估计关节 | 两阶段开销；漏检人体时后级无法补回 |
| YOLO11-pose | 检测框与关键点预测结合 | 现有接口、权重和推理工具完整 | 模型分数不能直接解释为工艺动作正确概率 |

例如，一个模型准确给出手腕和肩膀，也只能支持“手抬起”的几何判断；它没有因此确认“取了正确螺丝、放在正确孔位并完成紧固”。

优化姿态前端时，应在同一现场标注集比较关节误差、关键关节可用覆盖和下游事件效果，而不是只比较画面是否一直检出人。

实现：[rtmlib_pose.py](../algorithms/rtmlib_pose.py)、[pipeline.py](../algorithms/pipeline.py)。

### 2.2 跟踪：如何避免把甲的动作接到乙身上

[PoseTracker](../algorithms/tracking.py) 用历史速度预测框中心，再综合三个条件：人体框是否重叠、中心移动是否合理、骨架相对人体中心的形状是否接近。

```text
预测中心 = 上次中心 + 平滑速度 × 时间间隔
关联代价 = 0.45 × (1 - IoU)
         + 0.40 × 归一化中心距离
         + 0.15 × 骨架形状差异
```

中心距离和骨架差异除以人体尺度，横向距离考虑画面宽高比，减少分辨率和人物大小变化的影响。

匈牙利算法在所有检测与历史轨迹之间做全局一对一分配。相比“每个检测就近找人”，它避免两个新框同时占用同一条历史轨迹。

若某个匹配与竞争匹配的代价只差不到 0.06，当前实现将关联标记为模糊；动作历史清零，不能继续累计工序步骤。这体现的是身份连续性的证据门槛。

**误差传播：**一次换 ID 或串 ID 会影响速度、动作持续时间、顺序和完整周期统计。因此跟踪质量应在事件研究中独立计量，例如 ID 切换次数、轨迹碎片数和人物归属错误。

**建议实验：**

- 固定工位先加入明确的操作区域约束，减少无关人员参与关联。
- 对快速转身、人物交叉和短遮挡单列压力样例；区分检测漏人和关联错误。
- 比较现有运动／骨架关联与外观辅助关联，使用相同检测输入；只有身份歧义确实是主要误差时再增加外观模型。
- 多人同时操作时，要先标注工具与操作者的归属；人体 ID 稳定不代表工具已经关联正确。

### 2.3 平滑：为什么骨架更稳也可能更慢

当前主链使用 [smooth_keypoints()](../algorithms/pose.py)，属于自适应指数平滑：

```text
平滑点 = 上次平滑点 + alpha × (当前点 - 上次平滑点)
alpha  = 1 - exp(-dt / tau)
```

`tau` 大时更稳、追随更慢；运动幅度增大时，代码把 `tau` 从约 0.09 秒减到约 0.015 秒，让快速运动更快通过。只平滑前后都可见的关键点，不凭历史恢复遮挡点。

同文件已有 One Euro Filter。它先估计并平滑速度，再随速度提高低通滤波截止频率，达到“慢动作压抖动、快动作减少拖尾”的目的。它目前没有替换主链平滑。

**选择滤波器的正确依据：**关键点轨迹误差、动作起止偏移、短动作召回与发布延迟一起比较。不能只凭骨架看起来更平滑选方案。

建议用同一批原始关键点比较“不平滑／当前自适应平滑／One Euro”，固定动作解码器；再固定平滑方法调整解码器，避免同时修改两个环节后无法归因。

### 2.4 姿态几何：从关键点生成连续证据

[action_observation()](../algorithms/pose.py) 的关键设计是先输出各动作的独立支持度，而不是立即按某个固定优先级选一个标签。

定义肩中心 S、髋中心 H，躯干尺度为 `L = ||H-S||`，并给 L 设置下限，避免异常小尺度导致比值放大。

抬手证据使用手腕高于同侧肩膀的尺度比例：

```text
r_raise = (肩膀纵坐标 - 手腕纵坐标) / L
score_raise = wrist_reliability × ramp(r_raise, 0.05, 0.20)

ramp(x, low, high) = clip((x-low)/(high-low), 0, 1)
```

伸手证据采用肩腕横向距离，前倾证据采用肩髋连线偏离竖直的角度。移动候选采用历史髋部横坐标的两两斜率中位数，再除以人体框高度。

中位斜率比只看前后两帧更能抵抗单次检测抖动，但其历史窗口、相机运动和人体框尺度仍会影响结果。当前主要检测横向位移，不能当作全面的真实三维行走识别。

这些规则适合作为通用姿态观测或研究基线；要识别工艺动作，应增加局部工具／接触区证据，不能只不断调肩腕角度。

### 2.5 持续确认与滞回：抖动和漏掉短动作的取舍

[ActionDecoder](../algorithms/temporal.py) 先对支持度按时间平滑，再要求新动作至少两次观测、有效持续至少 0.3 秒。原始与平滑支持均达到 0.6 才进入候选；竞争分数相近时保留当前动作。

这相当于一个带记忆的状态机：

```text
证据不足 → 新候选 → 累计有效持续时间 → 稳定动作
   ↑          ↓             ↓              ↓
无效重置   候选改变       证据中断        低支持释放
```

在 5 Hz 下，每个采样间隔 0.2 秒，0.3 秒确认通常至少要等到第三个采样点；真实动作还可能发生在两个采样点之间。确认等待与采样误差应分别分析。

平滑和持续确认会共同影响延迟，但不能把 `tau + min_hold` 简单相加当作真实事件延迟，因为达到门槛的时间依赖原始证据强度与噪声。

转移阻尼还会压低某些新标签的竞争分数。它能减少误切换，也可能延后真实动作转换，属于需要消融的启发式。

**建议优化：**

- 以真实短事件召回和误切换率选持续时间，不以“时间轴更整齐”作为唯一标准。
- 比较原始支持、平滑支持、持续确认、转移阻尼逐项作用。
- 数据支持时尝试置信裕度累积或边界驱动确认，让强证据更快发布；不能预设低门槛一定更优。
- 目标为 0.2 秒事件时，先提高有效采样覆盖；5 Hz 的输入本身可能看不到完整短事件。

## 3. 从动作到流程：顺序判断为什么必须保留未知

### 3.1 当前人物动作顺序引擎

[ActionSequence](../algorithms/action_sop.py) 对每条人物轨迹维护当前步骤、已观察步骤、持续证据和释放状态。

默认示例是“抬手 → 伸手 → 前倾 → 移动”。当前步骤持续满足要求后才推进；后续步骤先出现时记录错序候选；连续相同动作需要明确释放后再累计下一次。

它处理的是人物动作观察顺序。对于灯具八位置任务，还缺少目标位置、工具归属、产品周期和设备结果，不能直接复用示例动作列表代替正式工艺。

### 3.2 三值规则的意义

[process_rules.py](../algorithms/process_rules.py) 用 TRUE／FALSE／UNKNOWN 处理不确定时间区间。

假设 A 的结束可能落在 `[4.8,5.2]` 秒，B 的开始可能落在 `[5.0,5.4]` 秒：两者存在重叠不确定性，不能强行确定 A 先于 B。

```text
若 A 最晚结束 <= B 最早开始：顺序 TRUE
若 A 最早结束 >  B 最晚开始：顺序 FALSE
其余：UNKNOWN
```

这个思想应延续到研究模型的观察事件层：

- 证据清楚且前置未做、后续已做：可输出错序候选。
- 全程可判定且到周期检查点仍缺必要事件：可输出漏步候选。
- 关键区间遮挡或周期不明：输出未知，不能用“没看到”直接判漏做。
- 操作候选观察完成：与设备 OK／NG 结果分开记录。

### 3.3 SOP 先验放在什么位置

不建议在视觉阶段强迫类别只能 A→B，否则真实 B→A 会被模型或滤波器改成“正常顺序”，异常被消除。

推荐将视觉事件识别与规则检查分开：模型允许任意位置、重复和逆序；规则根据工艺规范和证据覆盖进行诊断。允许返工或重复时，用前置约束图，而不是只允许一个不可回退的步骤索引。

**可研究问题：**在同样事件输入下，线性步骤状态机与允许重复的前置关系图，谁更少误报合法返工，同时保持错序召回？

## 4. 神经时序模型的原理与当前实现

### 4.1 因果 TCN：卷积为什么能识别动作片段

单帧可能分不清“工具靠近”“正在操作”和“正在撤离”，但过去一段的轨迹和外观变化能提供区别。

因果卷积只读取当前和过去。核长 3、扩张率 d 时：

```text
y[t] = W0 × x[t] + W1 × x[t-d] + W2 × x[t-2d] + bias
```

每层扩大历史覆盖，不需要使用未来帧。残差连接保留原特征，LayerNorm 改善数值稳定，GELU 提供非线性。

每块一层核长 3 的扩张卷积时，感受野为：

```text
R = 1 + 2 × sum(dilation)
```

| 扩张率 | 感受野点数 | 10 Hz 下最早到当前的跨度 | 20 Hz 下跨度 |
|---|---:|---:|---:|
| `[1,2]` | 7 | 0.6 秒 | 0.3 秒 |
| `[1,2,4]` | 15 | 1.4 秒 | 0.7 秒 |
| `[1,2,4,8,16,32]` | 127 | 12.6 秒 | 6.3 秒 |

跨度为 `(R-1)/采样率`，不等于必须等待这么久才能输出。当前灯具合成数据是 4 Hz，因此现有 15 点模型的跨度为 3.5 秒；同一结构换采样率后，不能沿用相同的动作时间尺度解释。

公开 12 类 TCN 每块两层卷积，感受野计算不同；不要把上述公式不加区别套用到它。

### 4.2 TCN、GRU、Transformer 如何选择

| 模型 | 历史记忆方式 | 适合用来验证的假设 | 注意事项 |
|---|---|---|---|
| TCN | 有限扩张卷积历史 | 短动作形态和有限操作上下文是否足够 | 感受野要按真实时间选择；逐层缓存可避免历史重算 |
| GRU | 递归隐状态 | 更长、不规则历史是否有用 | 长期状态可能累积噪声，周期切换必须重置 |
| 因果 Transformer | 对过去特征做注意力 | 不同时间点之间的长程关系是否值得额外开销 | 必须因果掩码，限制缓存；小数据下额外容量不必然有利 |

先以同输入、同划分、相近训练预算比较，再考虑更大结构。HA4M 12 类和五阶段研究使用不同任务，历史成绩不能直接决定现场最优架构。

### 4.3 拼接基线：已有模型做了什么

[ConcatSingleScaleTCN](../experiments/lamp_assembly/models.py) 为每个目标位置 i 构造一份输入：

```text
各节点特征 + 节点相对目标的 XY + 掩码 + 年龄 + 质量
         + 目标描述 → 线性投影 → 共享单尺度 TCN → 多任务头
```

相对几何使同一工具轨迹在不同目标下有不同解释；共享时序参数让各位置使用同一套识别机制。

它是必要的主对照：如果加入 RGB、工具尖端和更丰富标注后性能提升，不能直接归因于关系注意力，因为简单拼接也得到了同样新信息。

### 4.4 质量门控关系编码：如何选择可信节点

[GatedRelationBoundaryTCN](../experiments/lamp_assembly/models.py) 为目标构造查询 q，为节点构造键 k、表征 v，并结合相对坐标、年龄和质量。

基础可靠度：

```text
r[j] = mask[j] × confidence[j] × (1-corruption[j]) × exp(-age[j]/tau)
```

再乘学习门控 g，并计算目标查询与节点的相关性：

```text
s[i,j] = dot(q[i], k[i,j]) / sqrt(width)
alpha[i,j] = exp(s[i,j]) × r[j] × g[i,j]
             / sum_j(exp(s[i,j]) × r[j] × g[i,j])
z[i] = q[i] + sum_j(alpha[i,j] × v[i,j])
```

工具尖端节点可帮助确认位置，手腕提供接近／撤离上下文，局部图像提供接触外观。掩码为零或可靠度为零的节点不应参与有效聚合。

**当前结构有两个值得研究的限制：**

1. 在节点嵌入和相似度固定时，所有节点可靠度同时乘一个相同小系数，归一化后的注意力权重不变。当前机制更直接表达“相对谁可信”，不保证表达“全部都不可信”。质量元信息仍可能被网络学习利用，但不能把这个性质当作已经验证的绝对拒判能力。
2. 当前全缺失回退依据整体证据是否存在，不是逐目标的接触证据。另一处有可见节点，不代表 A 位置也有足够证据。

建议比较以下改法，作为实验而不是直接宣布更优：

- 加入“无可信证据”空节点，让注意力能够选择拒判。
- 将节点聚合后乘目标级可靠证据量，并对尺度做约束，避免把权重大小混同为概率。
- 明确输出目标级可判定性，结合目标配准是否有效、工具是否足够接近和接触区是否可见。
- 保留硬性安全条件与可学习质量头两个来源；对低置信但非零输入进行校准，而不只处理全零输入。

### 4.5 短长尺度与边界提示：结构存在不等于边界收益成立

短分支响应快速变化，长分支保持操作上下文。当前融合方式为：

```text
hint = sigmoid(boundary_hint(short))
gate = sigmoid(scale_gate(concat(short, long, hint)))
fused = gate × short + (1-gate) × long
```

最终动作、位置、边界和质量头读取融合特征。

当前 `boundary_hint` 有通过融合路径传播的训练梯度，但没有与最终边界头相同的独立边界 BCE 监督；“存在边界提示层”不能直接解释为“它已经学到可靠边界”。需要验证提示值与人工边界的对应关系。

建议分别比较：单尺度、双尺度无边界提示、双尺度有提示、提示增加直接边界监督。随后再比较事件发布是否使用边界预测，区分“训练表示的收益”和“事件解码的收益”。

### 4.6 多任务损失与事件发布不是同一目标

当前训练目标：

```text
L = L_action + 0.5 × L_position + 0.5 × L_boundary + 0.5 × L_quality
```

动作／位置／质量为掩码交叉熵，边界为掩码二元交叉熵，按最低验证总损失选模型。

当前事件输出却要求同时满足：动作是操作、位置正确、质量可用、当前观测新鲜。只要任意一项错，事件就不发布。

因此总损失下降可能来自背景、无目标或易判断质量类别，而实际操作事件仍为零。需要同时监控四个头的混淆矩阵、各任务召回以及发布漏斗，不能仅看一条 loss 曲线。

验证集包含五个周期、240 个时间点、464 个有动作监督的“时间点×位置”样本，其中背景 369、接近 24、操作 47、撤离 24。

| 验证诊断 | 拼接 TCN | 关系＋短长 TCN |
|---|---:|---:|
| 动作帧位置准确率 | 78.45% | 79.09% |
| 动作四类宏 F1 | 21.98% | 22.65% |
| 正确识别的操作采样点 | 0/47 | 0/47 |
| 位置 A 正确采样点 | 19/55 | 0/55 |
| 位置 B 正确采样点 | 11/40 | 0/40 |
| 发布前原始操作候选采样点 | 5，均为错误候选 | 0 |

永远预测背景即可达到 **79.53%** 的动作准确率。因此约 79% 的表面准确率目前不能证明动作识别有效。

即使在诊断中用真实动作替换动作预测，经过模型位置与质量门控后，也只有拼接模型保留 14/47 个操作采样点，关系模型保留 0/47。这是定位瓶颈的反事实检查，不能作为真实推理结果或论文成绩。

质量头输出表面 100% 正确，但该合成数据的不可用状态与全缺失回退一致；必须增加部分遮挡和跨模态冲突，才能评价可学习质量判断。边界正例仅占 16/928=1.72%，当前两模型尚没有可靠的正负边界分离。

由此得到的优化顺序：**先使非背景动作和位置学会，再验证边界，再研究事件发布，最后研究计算优化。** 当前证据不足以断言具体哪个超参数是唯一原因，也不足以承诺延长训练必然解决。

## 6. 可执行的优化研究阶段

### 6.1 阶段 A：建立能够学会任务的训练基线

这是工程诊断阶段，不作为现场精度贡献。

| 实验 | 具体做法 | 要回答的问题 | 阶段通过条件 |
|---|---|---|---|
| A1 少量训练周期拟合 | 在少量训练周期上，先训练动作／位置；不读取测试集 | 输入和标签是否可学习，前向／反向是否正常 | 各个已监督非背景类和 A/B 位置均能被拟合，事件解码能输出正确训练事件 |
| A2 单任务对照 | 分别训练动作、位置，再联合训练 | 是否多任务竞争压制难任务 | 给出各头学习曲线和任务间变化，而不只总损失 |
| A3 类别平衡 | 比较普通 CE、训练频数平方根权重、按周期／事件采样 | 背景占优是否是主要因素 | 验证操作召回提高，同时报告背景误报与精确率 |
| A4 训练预算 | 开发阶段比较 3／30／60 epoch，配合早停和学习率检查 | 当前是否主要为训练不足 | 最佳验证表现与训练表现一起报告；不保证更多轮一定有效 |
| A5 选型指标 | 比较验证总损失与带覆盖约束的验证事件指标 | 哪种选型更接近实际发布目标 | 冻结选择规则，避免总损失奖励易任务而忽略操作 |

少量周期拟合可先提出“约 95% 的非背景监督点拟合且正确恢复已知训练事件”的诊断目标；它只是排查实现与容量的建议门槛，达到后仍须做独立验证。

类别权重只根据训练集计算；采样时保留真实时间戳、完整事件、背景和未知区域，不能通过删掉困难样本美化结果。

事件 F1 在早期零输出阶段较粗糙，可先用操作召回、位置宏 F1 和背景误报进行开发监控，再逐渐以完整事件指标选型。不能无限扩大搜索空间并反复查看同一验证集。

### 6.2 阶段 B：补齐真实可观测输入

从单工位 A/B 开始，先试拍 10 个完整周期：确认工具尖端、接触区、目标区域是否能被观察，区分正常操作与空停留、掠过和遮挡。

建议输入包括：

| 输入 | 提供的信息 | 实现要点 |
|---|---|---|
| 工具尖端 | 具体作用位置 | 单独关键点／局部检测监督；工具框中心不能代替尖端 |
| 目标标定 | A/B 或八位置的几何语义 | 固定治具首轮可人工标定；平面配准适用时再引入单应 |
| 工具／手局部 RGB | 接触与动作外观 | 先冻结轻量视觉编码器，避免少量数据训练过多参数 |
| 人体手腕／上肢 | 接近、撤离、操作者上下文 | 与工具和目标使用同一坐标系 |
| 有效掩码、年龄、画质与配准状态 | 哪些观测可信 | 明确质量含义，不能只用检测分数替代全部质量 |

非平面灯体不能直接假设一张单应矩阵覆盖所有接触位置。配准失效时应标记位置不确定，不能将错位特征继续当作准确位置输入。

先建立“尖端距离＋接近／操作候选／撤离”规则基线，它帮助判断问题来自视觉定位还是时序分类。若接触根本不可见，应改变机位或加入独立设备信号，不能把这类情况当作普通分类调参。

### 6.3 阶段 C：位置关系与质量机制研究

建议假设 H1：**同样前端输入下，位置条件化关系和目标级质量机制改善相邻位置、局部遮挡与陈旧观测中的事件识别。**

比较必须保持同一数据、特征、时序结构、采样率和训练预算：

```text
普通拼接 → 无质量门控的关系聚合 → 当前相对可靠度门控
         → 增加空节点／目标级绝对证据机制
```

除主事件 F1 外，还要测：A/B 混淆、错位置事件率、相同覆盖率下错误率、全弱证据误报和单模态缺失结果。

数据中需要人为构造但符合现场机制的质量变化：单节点缺失、手可见而工具不见、低分数误定位、画面模糊、陈旧工具坐标、目标配准失败。将所有坏样本做成全零掩码，不能证明门控学会了真实质量。

共享目标查询应接受目标几何／类型，避免把位置编号或固定操作顺序作为识别捷径。测试目标重新排序、合法 B→A、位置扰动和新增位置，检查模型是在利用相对关系还是记忆固定模板。

### 6.4 阶段 D：短事件与重复尝试研究

建议假设 H2：**边界监督、短长尺度和在线解码共同改善短事件召回与重复尝试分离，并在可比误报条件下改善发布时间。**

分别研究三个层面：

1. **结构层：**同宽度／近似参数预算下比较单尺度、双尺度；按真实动作时长选择感受野。
2. **监督层：**比较无边界损失、最终边界头监督、提示层直接监督。边界正例稀疏时比较训练集正例加权 BCE 与有限因果容忍标注。
3. **事件层：**比较持续确认、置信裕度累积、边界与状态联合发布；各自独立调验证参数并冻结。

采用因果边界容忍时，可在真实边界发生之后给有限确认宽限，明确记录发布时间；不能把边界前的帧标成“已经知道未来结束”。离线完整视频估计与在线发布必须分别评价。

内部平滑损失只约束同一标注事件内部，不跨真实开始／结束、撤离区和两次独立尝试，否则可能把合法重复压成一次。

建议在线状态为 `空闲 → 接近 → 操作候选 → 撤离／结束 → 空闲`，按目标保存事件；同一位置再次操作生成新 event_id，但覆盖计数仍只说明该位置有操作候选，不能按次数虚增完成位置。

未知间隔如何处理应先冻结：短间隔只能在连续性有证据时暂停，长间隔中止／待复核；不能用未来动作恢复已经发布的“当时确定”结论。

### 6.5 阶段 E：科学比较与论文主张

建议论文方向：**面向固定灯具工位的位置条件化、质量感知的因果操作事件识别。** 边界与短长尺度作为可验证模块，而不是预先认定全部都有提升。

关系注意力、质量门控、边界监督和多尺度卷积均有已有研究；项目的贡献需要来自工业问题定义、具体耦合设计、独立现场数据和可靠消融，不能把模块名称本身视为新颖性。

若关系结构在真实同输入比较中没有优势，应保留负结果并采用更简单的模型；若只有工程落地收益，论文应按应用研究陈述。已有研究方案中的指标目标是待验证目标，不是承诺。

## 7. 数据与实验矩阵

### 7.1 数据规模和划分

开发 POC 可从 40 开发／20 验证／40 盲测周期开始，要求会话和完整周期隔离。这个规模用于判断可行性，不能单凭 100 周期就声称跨人员泛化。

论文阶段可把 6～10 名操作者、400～800 个完整周期作为初始采集量估计，再根据类别支持、学习曲线和区间宽度调整。若主张跨人泛化，测试操作者的所有周期都不能流入训练或验证。

标注至少包括周期、位置、独立尝试、动作区间、边界不确定性、是否可判定，以及异常类型。对接近和操作难以区分的样例开展双人复核。所有同源裁剪、增强和特征包随原始周期分区。

合成数据用于接口与诊断；固定生成日程会使跨虚拟操作者的样本高度相似，不能作为真实跨人泛化验证。下一版诊断生成器应随机化动作时长、位置顺序、尝试次数、背景长度和独立模态质量，保留清晰的潜在真值。

### 7.2 主基线

本文使用以下名称，避免与旧文档中不同的 B1 命名混用。

| 名称 | 方法 | 用途 |
|---|---|---|
| R0 | 工具／位置几何＋时间状态机 | 可解释现场起点 |
| N1 | 现场骨架＋单尺度因果 TCN | 衡量只有人体信息是否足够 |
| N2 | 相同 RGB／几何／骨架普通拼接＋TCN | 主要同输入对照 |
| N3 | 相同输入小型因果 Transformer | 检验优势是否只来自时序模型容量 |
| M | 位置关系＋质量机制＋短长尺度＋边界 | 完整候选方法 |

N1 与 N2 的比较评价新增信息，N2 与 M 的比较评价结构；二者不要混成一个“模型提升”结论。可复现的相关在线方法可另列；非因果方法只能单列离线参考。

### 7.3 核心消融顺序

| 组别 | 固定条件 | 改变因素 | 核心观察 |
|---|---|---|---|
| 输入 | 同一时序头 | 几何、RGB、骨架、手部逐项加入 | 哪类证据实际有用 |
| 关系 | 同一输入／时序头 | 拼接、关系、质量门控 | 相邻位置与局部遮挡收益 |
| 绝对质量 | 同一关系模块 | 当前门控、空节点、目标级证据机制 | 全弱证据拒判与风险—覆盖关系 |
| 时间尺度 | 同一特征编码器 | 单短、单长、双尺度 | 短动作与长上下文取舍 |
| 边界训练 | 同一骨干／解码 | 无边界、最终头、提示头直接监督 | 边界可分性及事件改善 |
| 事件解码 | 同一冻结模型概率 | 持续、裕度、边界状态机 | 召回、重复分离、发布延迟 |

主要比较至少三个种子；固定前端、数据版本、处理规则和选择预算。参数量不能完全匹配时，一起报告参数／计算量，并增加近似预算对照。

先逐阶段筛选有用模块，再冻结少量主要组合；避免在小验证集对所有网络、滤波器、阈值进行无限枚举。

## 8. 评价体系：怎样判断优化真的有效

### 8.1 主指标

采用同周期、同位置、同动作的一对一事件匹配，主指标为位置化事件 `F1@tIoU=0.5`。

```text
tIoU = 两事件交集时长 / 并集时长
Precision = TP / (TP+FP)
Recall    = TP / (TP+FN)
F1        = 2TP / (2TP+FP+FN)
```

实现基础已在 [evaluate.py](../experiments/lamp_assembly/evaluate.py)。同时报告较宽松的 tIoU 0.1／0.25，判断错误主要在动作／位置还是边界。

对真实可判定事件，检测失败导致不发布要计 FN。真实不可判定区的未匹配预测另列 ambiguous，同时给保守敏感性诊断。不能通过大量拒判获得漂亮的条件精确率。

### 8.2 建议必报结果

| 维度 | 指标 |
|---|---|
| 操作事件 | F1、precision、recall、位置混淆、重复尝试分离 |
| 真实短事件 | 预先冻结的时长分组召回和精确率 |
| 流程诊断 | 漏步／错序 precision、recall、F1，正常周期和合法重复误报率 |
| 未知处理 | 可判定覆盖、拒判比例、ambiguous 数量、相同覆盖下错误率 |
| 边界 | 起止偏移分布，未匹配事件另报 |
| 在线性能 | 完整处理 p50/p95、吞吐、积压／拒绝率、真实事件发布延迟 |
| 稳定性 | 至少三种子、按操作者／会话的配对统计区间 |

短事件分组可在试标后确定，例如 `<0.5 s`、`0.5～1 s`、`1～2 s`、`≥2 s`；分组在封存测试前冻结。

对错序，延迟起点是违规动作已有足够可见证据的时点；对漏步，是周期检查点；对操作结束，是足以确认结束的时点。边界偏移和模型前向耗时不等于真实报警延迟。

### 8.3 统计与结论门槛

相邻帧和同操作者的周期相关，不能把每帧当独立样本制造很窄的置信区间。按实际采集结构在操作者／会话层做配对 bootstrap，并报告每个困难条件的事件支持数。

达到同输入基线事件 F1 提高 5 个百分点、短事件召回提高 10 个百分点或同精度覆盖下 p95 延迟下降 20%，可作为取得基线后预注册的候选目标；这些数值尚未验证。

如果平均 F1 提高，但合法重复被合并、关键异常召回下降或未知比例大幅增加，应报告权衡，不能只保留最好看的指标。

## 9. 算法有效后再做效率优化

### 9.1 先定位完整耗时

将端到端过程拆为采集／编码、传输、工具／姿态前端、ROI 外观、时序、事件发布、显示。当前大部分历史数字是局部推理微基准，不能直接代表灯具服务性能。

```text
每路采样需求 = 目标有效 Hz
总处理需求   = 路数 × 每路有效 Hz
```

要在实际运行中检查处理能力是否覆盖需求，并观察尾延迟和拒绝率，不能简单用平均单帧时间的倒数推算多路吞吐。

### 9.2 优化优先级

| 优先级 | 改法 | 适用条件 | 必须保留的验证 |
|---|---|---|---|
| 高 | 灯具 TCN 逐层激活缓存 | 窗口重算确为瓶颈 | 整段／逐帧／随机分块一致、周期重置、边界条件 |
| 高 | 共享图像编码＋ROI 特征复用 | 多位置重复图像编码占时 | 相同输入下事件精度和小目标可用性 |
| 中 | 同尺寸 ROI 合批 | 多区域检测可并行 | 分数阈值附近结果、真实场景吞吐和显存 |
| 中 | 小模型蒸馏 | 教师已经有效且推理过慢 | 与直接训练学生比较事件 F1、覆盖和延迟 |
| 后 | FP16／INT8 | 设备和算子支持，已有有效模型 | 导出前后因果／数值、各困难条件事件指标 |
| 后 | 动态采样 | 确认短事件不会丢失 | 实际采样覆盖、召回、时间戳与间隔重置 |

公开研究的 `DensePredictor` 已有逐层缓存，可复用思想，但灯具模型还有目标条件与多路状态，不能直接换类名就视为完成。

缓存应绑定视频流、产品周期、模型／特征版本和标定签名。相机移动、周期切换、配置变化与长间隔必须触发正确失效；优化后不能把上一个产品的证据带到下一个产品。

## 10. 推荐执行顺序与可交付结果

| 阶段 | 当前优先工作 | 可交付结果 | 进入下一阶段的依据 |
|---|---|---|---|
| 1 | 四头诊断、少样本拟合、类别与选型检查 | 混淆矩阵、发布漏斗、可学习训练基线 | 非背景动作和位置均能学会；失败原因可定位 |
| 2 | A/B 试拍和真实前端 | 标定、工具／尖端标注、周期与可判定性清单 | 接触与位置有可用证据，困难负例明确 |
| 3 | 固定同输入基线与事件契约 | R0、N1、N2、事件发布和评测 | 可复现的开发／验证结果，统计口径一致 |
| 4 | 关系质量与短长边界消融 | 主要模块对照、压力集结果 | 收益来源清楚，失败和拒判代价同时可见 |
| 5 | 冻结现场测试 | 多种子、逐周期预测、分层指标和区间 | 新人／新会话封存测试支持相应主张 |
