# 综合优化验收记录

日期：2026-10-08。范围：保持现有 FastAPI、独立 Worker、原生 JavaScript 架构，改进稳定性、性能及交互体验。

## 主要改动

| 范围 | 改动 | 实际作用 |
| --- | --- | --- |
| 视频上传 | 百分比、已传大小、取消上传、服务器限额同步、扩展名预检 | 上传过程可见；取消后不继续创建任务 |
| 任务请求 | 请求超时、切换时 AbortController 取消、递增请求代次校验 | 同一任务反复选择时，旧响应也不能覆盖新状态 |
| 任务历史 | 文件名、状态标签、搜索、筛选、20条分页、刷新 | 可查找超过100条的历史任务，不必根据短编号猜测视频 |
| 实时检测 | 429 返回 Retry-After；繁忙／网络失败最多5次退避重试 | 短暂繁忙不会立即关闭摄像头，持续错误仍明确停止 |
| 页面后台 | 后台暂停新摄像头采样，任务状态轮询间隔延长到10秒 | 减少无人在看的页面对网络与推理服务的占用 |
| 视频回放 | 使用 requestVideoFrameCallback，暂停时停止循环重绘 | 不再按显示器刷新率不断重绘相同画面 |
| 结果渲染 | 轨迹 Map、按轨迹分组并排序的片段、缓存时间轴HTML、相同采样帧不重复更新结果 | 减少大结果集的全量扫描、排序与DOM重建 |
| 数据库 | 任务所有者／时间索引、状态／时间索引、会话过期索引；本机SQLite WAL | 支持分页及队列查询，降低本机读写相互阻塞 |
| 页面布局 | 内容自然展开、移动端表格说明不重叠、任务弹窗分页固定可见、状态色、可触达按钮 | 页面内容不依赖固定视口高度挤压显示 |
| 首次使用 | 默认通用姿态工位、空白工作区引导、服务器首页不加载参考视频 | 可直接上传或选择摄像头，避免将样例画面误当成当前任务 |
| 错误反馈 | 参数校验统一返回message且不回显请求内容；禁用本地存储时保持工位选择可用 | 错误能显示到界面，浏览器存储限制不阻断主要功能 |
| 开发流程 | npm test 自动创建独立预览服务；测试截图写入.runtime；npm run dev:local | 无需手动占用固定测试端口，不覆盖reference素材 |

上传后会根据视频元数据把默认采样率设置为不高于5fps，避免低帧率视频被默认5fps选项拒绝。

## 验证结果

1. `npm run test:api`：**43 passed，1 skipped**。包括新增的分页、筛选、文件名、字面量通配符搜索、用户隔离、索引升级幂等、既有数据保留、SQLite WAL、参数错误与上传限额测试。跳过项是未配置服务的PostgreSQL并发测试。
2. `npm test`：原静态界面、既有分析样例与模拟API交互全部通过；随后对最后的空白工作区和弹窗调整单独重跑 `node tools/preview-test.cjs ui-regression.cjs`，通过。
3. `npm run test:e2e`：最终代码在隔离数据库、临时凭证与独立API／Worker上完成真实YOLO11s-pose GPU推理；登录、坏视频拒绝、上传、刷新恢复、回放、CSV、报告、历史搜索、摄像头启动／停止／模式切换、算法测试与移动端检查通过。浏览器无未捕获JavaScript错误。
4. 性能行为回归：暂停回放稳定后观察1.2秒，**画布重复绘制0次，检测结果DOM变更0次**。这是固定测试条件下的行为检查，不是整个平台吞吐率基准。
5. 稳定性回归：先返回一次429再执行真实检测，确认自动恢复；模拟同一任务的延迟旧响应，确认不会覆盖当前取消状态；模拟上传进度事件与延迟服务端响应，确认取消上传后不创建任务。
6. 布局检查：任务列表在1440、1024、768、390像素宽度无横向溢出，分页按钮处于视口内；人工查看桌面、移动端和任务弹窗截图。
7. 本机运行：通过 `npm run dev:local` 启动API和Worker；`http://127.0.0.1:8000/api/v1/health` 返回200及ready。

## 启动与升级

本机已有依赖时运行：

```sh
npm run dev:local
```

打开 `http://127.0.0.1:8000`。本机登录信息保存在 `.runtime/local-settings.json`，本次沿用既有配置，不把密码写入文档。

其他部署在原服务环境执行 `npm run server:init`，为现有v1表补建索引，再重启API和Worker。索引升级不更改字段或业务记录；PostgreSQL建索引在大表上需要按实际部署安排维护窗口。

目录未初始化Git，本次修改前已把既有源码备份到 `.runtime/optimization-backup-20261008/`。新增测试和此记录不属于原始备份。
