# 场景任务规则与性能优化验证

本次根据模型与场景管理页优化场景规则和实时推理，并明确人员规则的范围。没有新增员工身份识别、跨摄像头关联或人员动作归属模型。

## 逻辑变化

- 发布前校验同区域互斥的类别要求与数量要求，允许草稿暂存后修复；类别编号和人数必须为整数，拒绝布尔值与隐式字符串转换。
- 检出、超量、禁用目标及禁用目标恢复，都按配置的连续帧数确认。未知、缺项、重复或错误类型结果不能继承旧的通过；异常输出、解码/加载/推理失败清除当前结果，结束接口不能再交付旧通过。
- 任务版本变化或模型停用立即停止旧实时轮次；已有离线视频保留冻结快照。不同场景和不同检测流独立维护规则、时间戳、确认帧和结果。
- 人员规则基于每个区域的人体检测框，可核对在场证据与人数上限；人数不足为待复核，人数超限连续确认后异常。该功能没有身份去重和动作归属能力，重叠区域数量不能相加当总人数。
- 创建场景加入账户隔离的幂等编号；相同编号/配置并发提交只产生一条场景。模型后来停用时仍可重试确认已创建任务，返回当前不可用状态。已编辑任务不会被重试覆盖。

## 性能变化

- 实时缓存由“场景快照”改为“账户、注册模型、权重哈希、路径、任务类型、CUDA设备”。同一模型关联多个场景、阈值或版本时复用权重；每次调用仍应用当前场景参数。共享YOLO对象有可变预测状态，因此继续串行执行模型推理。
- 同一帧映射到相同像素矩形的规则只推理一次，同尺寸区域继续按最多8张批次处理。置信度比较保留原始精度。
- 检测框批量转CPU；轮廓和关键点每批结果提取一次；按类别索引规则匹配，展示框去重使用有界的向量运算，展示与传输目标最多300个。区域计数独立于展示截断，单区域达到模型300个检测上限时保守判定。
- 保持FP32推理，兼容新旧Ultralytics精度参数，避免新版本每帧输出弃用告警。
- 管理页面搜索防抖180毫秒，任务搜索只重绘任务列表；回到可见页面按需刷新，退出清除目录和编辑内容，拦截旧会话的异步保存响应。编辑器显示区域数量、估计区域检测次数与连续确认跨度。

## 缓存对照实测

脚本：`node tools/python.cjs tools/benchmark-scene-runtime.py`。原始输出：`test-results/scene-runtime-benchmark.json`。

本机 NVIDIA GeForce RTX 5070 Ti、PyTorch 2.8.0+cu128；真实 `models/screw-head-v1.pt`，640×360参考画面，输入尺寸640。两个不同ROI/阈值的场景交替处理12帧、缓存容量1，共两轮、第二轮交换策略执行顺序。CUDA预热后每种策略从空缓存开始；两种策略使用当前规则计算器，旧策略在脚本内重建。检查了每个场景的状态/数量一致。

| 指标 | 按场景缓存 | 共享权重缓存 |
| --- | ---: | ---: |
| 每轮加载模型次数 | 12 | 1 |
| 每轮缓存命中次数 | 0 | 11 |
| 单帧中位耗时 | 115.624 ms | 12.457 ms |
| 每轮12帧总耗时中位数 | 1624.440 ms | 249.795 ms |

计时含加载、预测器初始化和规则处理，不含HTTP、数据库、JPEG解码或多工位/训练并发。这是模型反复加载场景下的缓存对照，不能外推为单模型已预热场景的加速倍率或生产吞吐。不同注册模型仍按LRU容量淘汰。

## 服务器运维

后续补验：同日已配置本机PostgreSQL 16.6专用测试库，原先跳过的5项全部通过，并增加场景幂等创建跨模型行锁竞争验证，专项合计6项通过、0项跳过。可执行 `npm run test:postgres` 复测，见 [配置与实库测试](../guides/postgres-testing.md)。上文跳过记录保留为首次验收状态。

启用实库后的整组相关回归结果为175项通过、0项跳过，JUnit记录位于 `test-results/postgres-enabled-regression.xml`，未遗留测试schema。

`SCENE_MODEL_CACHE_SIZE` 范围1–6，表示每个API进程的不同权重缓存槽数；同一注册模型的多个场景通常占一个槽。此值不是显存字节硬限制，设置前需使用实际模型测量峰值。实时状态仍在进程内，继续单API实例，API和Worker共享数据库及同路径模型目录。

更新本地服务前检查分析/训练/数据集任务、有效工位租约及四类实时流，均为0；随后重启API和Worker。健康状态均为ready，`/admin` 和缓存指标接口验证通过；日常模型和场景库保持为空，测试数据只存在隔离目录。

登录后 `/api/v1/metrics` 的 `sceneModelCache` 返回 `residentModels/capacity/modelLoads/cacheHits/evictions`。计数自进程启动累计；命中只说明模型对象已存在，不代表该帧推理成功。`residentModels` 表示缓存对象数，CUDA分配器可能保留已释放对象对应的预留显存，不能当显存使用量。多模型切换时观察加载/淘汰增量与端到端P95，再决定容量；没有取消推理串行锁，也没有进行自动扩容。
