# 工业训练与 8000 主服务联动

入口：`http://127.0.0.1:8000/training`，也可从 `/admin` 的“工业模型训练”进入。使用现有管理员登录、会话和 CSRF 校验。API、训练和检测使用同一数据库与 `DATA_DIR`，训练结果可进入现有模型库和场景配置流程。

## 操作流程

1. 准备真实标注数据及 JSON 清单。选择工位、初始权重、训练类型和数据路径；默认每集合至少 3 个批次、每类 20 个样本，检测类还需每集合 20 个真实负样本。
2. 提交后配方、随机种子、置信阈值及准入门槛不可修改。系统先审计，再复制、逐文件核对 SHA256，形成独立的数据和初始权重快照。
3. 训练仅使用 train / val；最佳权重由验证集选择。测试阶段才复制并评估 test，测试结果不用于训练或最佳权重选择。
4. 独立测试逐类精确率和召回率达到冻结门槛后，视觉模型以**停用**状态登记到模型库。失败、未达标、取消或失联任务不登记模型。
5. 在现场验证工件判定及性能，再进入 `/admin` 启用对应 `train-任务ID前8位` 模型，配置类别、数量、ROI、置信阈值和时序规则，显式发布场景。场景出现在 8000 首页任务选择器中，检测记录沿用已有模型及规则版本快照。

训练任务的 `station1`–`station6` 是数据与候选用途标识，不会将新权重绑定到现有人工周期。六工位人工流程继续独立运行。特征分类产物为 `.joblib`，需要匹配 `feature_schema` 的专用推理适配器，不能直接登记为通用视觉场景。后台当前支持 detect / obb / classify / feature-classify；分割、姿态仍走已有 CLI 并独立评估任务指标。

## 训练工作区界面

训练页与 8000 检测工作台使用同一套石墨灰、琥珀黄、绿色操作按钮和直角组件风格，支持桌面及窄屏布局。

- 概览统计全部记录的排队、执行、测试通过和需处理数量，可直接筛选；工位、状态和任务名称/编号搜索可组合使用。2026-11-06起列表改为服务器分页、每页25项，完整审计和评估按需读取，详见 [管理性能与服务器部署](../guides/management-performance.md)。
- 表单实时预览配置；提交前检查必填、整数和范围，错误位于折叠区域时自动展开。图像分类隐藏检测置信阈值和负样本要求，特征分类隐藏视觉训练参数。
- 提交期间冻结表单，同一配置在网络失败后重试沿用幂等键，成功提交后禁止连续重复点击。同步失败保留上次记录并自动重试；退出或会话失效清除表单、记录和详情，旧请求不会重新写回页面。
- 取消训练需确认；终态任务可复用冻结配方，保留随机种子、历史输入尺寸、绝对权重路径及未在表单展开的训练参数。覆盖未提交的编辑或重置时提示确认。
- 失败/未达标详情包含处理建议、审计结果、逐类指标及日志。视觉候选模型链接携带模型 ID，进入管理页后定位并展示对应模型；不会自动启用。

交互回归：`npm run test:training-interactions`（默认读取本机 8000 的静态页面；所有 API 都由浏览器测试夹具接管，不写正式数据库）。验证取消确认、筛选、参数切换、输入校验、重试、配方复用、退出竞态和模型定位；报告及截图位于 `test-results/training-interactions-20261105/`。

## 数据清单格式

清单位于项目目录或 `DATA_DIR` 内，样本和标签必须位于清单目录内部。路径在 API 所在主机解析；容器部署时请将同一数据集挂载到 API 和 Worker 相同路径，推荐共享 `DATA_DIR/datasets`。初始 `.pt` 必须来自可信本地来源，任务不隐式下载初始权重。

以下仅展示单条记录的格式，实际清单必须包含三个集合和所有类别，且满足数量门槛：

```json
{
  "schema_version": 1,
  "names": ["hole", "screw"],
  "samples": [
    {
      "id": "station1-batch001-cycle001-cam01-frame001",
      "split": "train",
      "source": "capture-session-001",
      "group": "capture-day-001",
      "station": "station1",
      "product": "product-A",
      "camera": "cam01-v1",
      "batch": "batch001",
      "cycle": "batch001-cycle001",
      "lighting": "normal",
      "occlusion": "clear",
      "file": "images/frame001.png",
      "label": "labels/frame001.txt"
    }
  ]
}
```

检测标签采用归一化 YOLO 格式；负样本必须有明确的空标签文件。分类标签是类别整数索引；特征分类文件为有限的一维 `.npy`，各样本维度一致。

- `source`、`group`、`batch`、`cycle` 不能跨集合；批次/周期标识应在本数据集中唯一，多个相机对同一工件的采集应共享周期标识。
- 非特征任务禁止相同文件内容、相同路径或解码后相同像素跨集合，换文件格式不能绕过检查。
- 派生样本必须记录 `parent_ids`；引用不能越过集合或形成循环。合成及派生样本仅允许用于训练，不计入真实负样本数量。
- `product`、`camera`、`lighting`、`occlusion` 是必填溯源信息；报告记录各集合的光照/遮挡分布。软件无法证明这些人工记录真实，也不会把填写完整视为现场覆盖充分。
- 创建任务时冻结清单和初始权重散列；样本内容在工作器审计时冻结。审计、复制及后续训练/测试之间的内容变化会中止任务。排队期间请勿修改原始数据。

## 指标与使用范围

默认逐类精确率、召回率门槛均为 0.95。检测/旋转框采用冻结置信阈值（默认 0.60）与匹配 IoU 0.45 的混淆矩阵计算，包含背景误检及漏检，不使用测试集最优 F1 位置的 P/R 作为准入条件。图像分类使用 top1 混淆矩阵；特征分类使用逐类分类报告。总体 mAP/accuracy 保留用于分析，不能替代缺失的逐类证据。

最小支持数和逐类指标只是模型测试门槛，**不代表工件误放行率、完整工序合规或量产验收**。还需按实际产品、班次、相机、光照、遮挡和异常类型验证；置信阈值/ROI/数量/时序规则改变后，需重新做场景级验收。测试集应保留为真正独立留出数据；反复根据同一测试结果调参后，需要新的独立留出集。

库返回的平均验证耗时仅是验证吞吐指标，不是实时摄像头端到端 p95。现场需另测漏检、误放行、断流/遮挡降级、并发负载及采集到页面判定的时延。未新增自动生产放行逻辑。

## 调度、取消与审计

正常 `backend.worker` 启动一个训练监督线程，检测轮询继续独立工作；每个训练任务在子进程执行。数据库唯一执行槽保证最多一个后台训练。模型训练强制使用CUDA GPU，禁止CPU回退。GPU对训练子进程保持可见，训练显存分配默认限制为总显存25%；辅助CPU线程限制为2，DataLoader workers=0；模型卡记录实际GPU和线程数。这是计算并行度限制，不是硬件 CPU/RAM/磁盘资源配额，重负载现场应安排维护时段或专用训练机。已有 CLI 可用于独立训练机。

任务状态：`QUEUED → RUNNING(AUDIT/TRAIN/TEST/REGISTER) → CANDIDATE / REJECTED / FAILED`；取消为 `CANCELLED`，执行中的取消先经过 `CANCELLING`，监督器停止子进程后释放执行槽。租约过期标记失败/取消，令牌及有效租约阻止旧工作器提交。失联任务不自动重跑，不自动 resume；排查后创建新任务。

创建请求要求 UUID `Idempotency-Key`：相同请求重试返回原任务，同一键改变内容返回409。取消可重复执行；候选登记与完成状态在同一数据库事务提交。模型库仍需要管理员显式启用；这不是对管理员导入任意外部权重的禁止机制。

API：

| 方法 | 路径（前缀 `/api/v1/admin`） | 内容 |
|---|---|---|
| GET | `/training-runs` | 最近100项任务、默认门槛、执行模式 |
| POST | `/training-runs` | name、station、recipe、policy；202入队 |
| GET | `/training-runs/{id}` | 进度、冻结配方、数据审计、模型卡、独立测试 |
| POST | `/training-runs/{id}/cancel` | 取消当前任务 |
| GET | `/training-runs/{id}/report` | 下载JSON记录 |
| GET | `/training-runs/{id}/log` | 最近64KB工作器日志 |

所有接口校验所有权。修改接口校验CSRF；未授权不能访问产物，静态服务器不暴露 `DATA_DIR`。训练快照、日志、模型卡保存在 `DATA_DIR/training/{id}` 和 `DATA_DIR/training-logs/{id}.log`；登记模型保存在 `DATA_DIR/registered-models`。现有检测清理器不删除训练审计材料；训练数据保留需按项目生命周期另行管理。
