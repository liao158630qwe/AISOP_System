# 六工位实时接入与集中推理实施记录

日期：2026-11-06。当前交付范围为设备身份、采集、实时判定与预览隔离、负载保护、可配置算法组并发及验证工具。使用方法见 [接入指南](../guides/six-station-realtime.md)，原始服务容量数据见 [JSON 记录](six-station-benchmark-2026-11-06.json)。

## 已实现

- 固定 `stationId → workstationId → cameraId`，六个工位分别签发凭据，摘要存储；终端只能访问自己的工位。绑定更新轮换凭据和版本，原会话及流失效。
- 终端页 `/terminal`、管理员页 `/terminals`，管理后台增加导航；人工流程也锁定终端所属工位。
- USB 浏览器采样与 RTSP/USB 常驻采集器。网络终端通过鉴权接口显示当前成功检测的采样 JPEG，区分检测采样与原始视频。完整媒体网关未包含在此交付中。
- SQL 流代次、幂等开流和 30 秒租约，旧流/重复/乱序帧拦截。请求取消不提前释放仍在运行的 GPU 任务；租约过期后可重建新流。
- 每工位最多一张待处理新帧，替换不改变排队位置，队列超时拒绝。不同算法组允许 1–3 个有界并发，同一工位和算法组保持串行。默认仍为 1。
- 有效采样缺口将 PASS 降为 REVIEW；浏览器隐藏、摄像头中断、状态超时、流或周期身份不符会清除旧结果。停止失败可重试释放，避免遗留流阻止新采集。
- 有界场景模型 LRU 缓存、工位状态/指标接口、六路固定到达率压测工具及隔离的本机 GPU 对照工具。

## 真实 GPU 配置对照

硬件：本机 NVIDIA GeForce RTX 5070 Ti，报告显存总量 16303 MiB；测试前已有约 3.1GiB 显存占用。本机测试与目标生产服务器不同。实验使用单 API 进程、隔离 SQLite、姿态/螺丝/贴条各两路，逐路固定 4fps 候选采样，测量窗口 20 秒，HTTP/服务延迟门限 500ms。

输入为六张重复 JPEG：姿态使用 `assets/factory.jpg`，螺丝使用 `models/screw-reference-overhead-v4.jpg`，贴条使用 `models/sticker-reference-v1.jpg`。按各任务尺寸限制编码，使用项目现有真实 GPU 模型。没有真实相机、视频解码、连续录像或屏幕显示时延；重复静态图也不验证动作规则和识别准确性。

最终对照按相同代码、相同输入顺序运行，未同时运行自动化测试或另一场 GPU 压测：

FPS 按测量窗口内完成数计算；p95/p99 从候选到响应，包含网络与排队，只对成功请求计算，拒绝和跳过单独公开。并发配置窗口内完成 352 张，另有 2 张在窗口结束后完成。各工位最长无结果间隔分别为 312、594、625、297、578、625ms。

准备时间单列：并发配置六次首次采样约为 2031、875、1203、15、125、219ms。此后再开新流测量，准备时间不混入上述稳定窗口指标。进程中模型缓存、参考资产和 Windows 调度可能导致不同批次波动；本次是短时单组对照，不是长期性能保证。

同代码对照约提高总有效吞吐至 **1.99 倍**。姿态两路达到目标，螺丝两路仍不足 4fps，贴条两路不足 4fps 且 p95 超过 500ms，因此六路整体 `allTargetsMet=false`，压测工具按约定返回退出码 1。没有以低延迟拒绝或总均值替代逐路验收。

此前还试过“并发 3、人体池 1”，出现共享人体槽位争用。螺丝/贴条内部也调用同一人体池，因此配置必须结合起来验证。提高池大小增加模型副本和显存开销，正式环境仍保留默认串行，未擅自套用实验并发参数。

原始实验目录：串行 `test-results/station-gpu-benchmarks/mixed-rnhf86e9/`；并发 `test-results/station-gpu-benchmarks/mixed-6vmev_r_/`。两份报告、配置和 GPU 摘要已复制到本记录旁的 JSON 文件，便于复核。

## 本机可用状态与未完成项

本机已执行增量表初始化并启动最新 API/Worker，8000 服务 readiness 为 ready。`/terminal`、`/terminals`、管理员绑定和指标接口已通过实际请求验证。没有写入虚构的生产设备绑定或将实验任务分配给真实工位；现场需按管理员页登记实际相机和已验证任务。

剩余现场工作是六路真实相机地址与任务配置、目标服务器配置、识别准确性以及连续运行验收。贴条/螺丝仍需按真实任务组合分析每帧耗时，推进共享解码、兼容模型合批或多 GPU 分配；不能由此次队列和并发改造推导出六路 10fps 已达标。

原始 60fps 回溯录像、流畅媒体网关和六工位完整工艺算法尚未实现。后续业务优化已将 `finish` 算法结果与中断原因持久化，详情见业务流程补充记录；工件仍使用既有人工流程放行。生产发布前还需独立 PostgreSQL、真实网络及存储压力、8 小时和 72 小时连续验证。
