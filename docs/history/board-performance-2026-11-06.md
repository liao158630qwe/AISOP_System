## 可复现测量

Windows 本机，隔离 SQLite 测试库；6 万条工序、6 万条事件、1 万条检测归档，每条归档另含 8 KiB 合成 JSON 内容。覆盖 5 天，每天 2,000 个工件、每件六工位。六工位绑定记录真实读取，但没有采集流或模型推理。测试时间固定为当日模拟 20:00，结果与运行时间段无关。

```powershell
npm run benchmark:board -- --label optimized
```

测试同时核对汇总结果：总工件 2,000、合格 1,520、不合格 480；工序通过 11,520、不通过 480，合规率 96%。原始结果位于 `test-results/board-performance/optimized.json`。

计时范围为 Python 内部快照构建与缓存调用，不含 HTTP、鉴权、网络、浏览器或 GPU；Python 分配峰值不包含 SQLite 原生内存和进程总内存。旧实现的基准进程未正常结束，因此没有有效的前后倍数对比。这些数据不能作为服务器吞吐或并发能力承诺。

## 服务器复验

数据库内汇总保留重检覆盖、跨日工件、人工复核结果和所有者隔离口径。新增索引通过 `backend.init_db` 幂等补建。生产数据和趋势最多缓存 15 秒，状态和告警约每 3 秒拉取；短时并发请求共享 1 秒快照缓存。

在目标服务器先按 [部署说明](../guides/central-board.md) 初始化并启动单实例 API，再用独立 PostgreSQL 测试库运行 `tests/test_postgres.py`，验证 JSON 字段提取、工序汇总和 12:59/23:59 小时边界。当前环境未配置 PostgreSQL，也未执行 Docker 或远程服务器部署；上线前仍需在真实六路采集并行时观察看板延迟和检测吞吐。
