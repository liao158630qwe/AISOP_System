# 工位1人工流程试点

**当前工位1–6的人工工件登记默认暂停，首页直接检测仍可使用。** 页面不要求产品型号或工件编号；F8启动当前工位AI检测，结果在同一界面显示并按检测轮次归档。首次使用未配置的工位，在右侧选择已适配画面的检测模型并保存，再选择摄像头、视频或图片。视频按原速采样，结束自动归档；摄像头可按“结束并归档”结束。重复F8不会创建重复轮次。人工建件接口仍停用，既有人工记录与证据保留。

工位工艺清单不会自动转换成AI模型；模型能力以实际绑定任务为准。旧人工流程在下述开关恢复后可继续使用，独立 `/terminal` 入口也保留。

检测期间，“集中大屏”同步当前工位的判定、进度、采样在线状态和当日轮次。归档后保存最终结果，停止则记录中断；历史窗口支持展开及导出本轮完整记录。大屏明确标示视频/图片联调来源，统计按轮次而非生产件数。完整联动说明见[集中大屏](central-board.md)。

以下操作说明用于恢复人工流程后。需要恢复时，设置 `PILOT_REGISTRATION_ENABLED=true` 并重启 API；本机 PowerShell 可运行 `$env:PILOT_REGISTRATION_ENABLED='true'` 后执行 `npm run restart:local`，Docker 部署在 `.env` 设置该值后重新创建 API 容器。恢复默认暂停则设置为 `false` 后重启。

工位2–6已接入同一主界面，具体项目和待确认要求见[六工位人工流程说明](manual-stations.md)。以下工位1的两阶段规则继续保留。

工位1先检查 H01 至 H04 四个定位孔，再确认 S01 至 S04 四处螺丝。此版本先运行人工确认、阶段截图、结果保存和复核流程，**没有接入或训练孔位、螺丝模型**。通过结果为“人工参与通过”，算法结论始终为“未运行模型”。

## 启动与入口

使用现有本机启动方式：

```powershell
npm run dev:local
```

打开 `http://127.0.0.1:8000/`，在“检测任务”中选择“工位1 · 4孔检查后4螺丝”。检查画面、右侧两阶段流程、下方检测明细及阶段证据均在原主界面内显示；旧 `/station-1` 地址自动跳转到 `/?task=station1`。各任务共用登录账户，登录配置仍在 `.runtime/local-settings.json`。工位1人工流程不需要 Worker 或模型推理；视频模型检测仍使用原来的 Worker。

切换任务会停止当前采集并清除画面上的旧结果。工位1未结束的服务端周期保留，切回后须核对同一工件再继续；提交阶段记录期间不能切换任务。后续模型在本任务接入，操作入口保持不变。

启动脚本会重复安全地执行数据库初始化，新增 `pilot_cycles` 和 `pilot_events` 两张表，保留原有分析记录。已经运行的旧 API 不会自动热更新；需在旧任务处理结束后重启本机服务。自行部署 API 时，在同一环境下先执行 `npm run server:init` 再启动 API。

## 操作一次完整检查

1. 先在实物或工艺位置图上明确 H01 至 H04、S01 至 S04 的对应位置与通过标准。本版本尚未提供位置标定或自动定位。
2. 选择“现场摄像头”，开启摄像头。没有现场工件时可选择图片或视频联调；这些记录会标记为联调来源。图片和视频在浏览器本地读取，只上传确认时的截图。
3. 填写产品型号，扫描或输入工件编号，点击“开始本件”。留空编号时生成 `TMP-` 临时编号；它只用于本站追溯。
4. 在孔位被装配遮挡前逐项勾选 H01 至 H04，点击“确认并保存阶段证据”。核对截图、填写实际确认内容和当前账户密码，提交成功后进入螺丝阶段。
5. 装配后逐项核对 S01 至 S04 的当前状态，再保存截图。图片联调须重新选择螺丝阶段图片；回放的螺丝取证时点必须晚于孔位取证时点。
6. 显示“检查完成，待保存”后，核对仍为同一工件并点击“结束并保存”。确认后才显示“人工参与通过”。螺丝证据超过3分钟须重新取证；此前的截图和确认仍保留在操作记录中。
7. 点击“下一件”。新周期清空所有确认项，不能继承上一件的检查结果。历史记录可搜索工件或产品，查看两阶段截图和操作时间，导出记录 JSON。

孔位可见和螺丝视觉安装状态须由现场人员判定。此流程不证明孔尺寸、扭矩或有效锁紧，也不会自动发现错序、遮挡、拆卸或换件。

## 异常 复核与返工

在活动周期中点击“异常或中断”，填写原因，可选择“待复核”“确认异常 NG”或“中断本轮”。有当前画面时保存截图；相机断开等无法取证的情况明确记录“证据缺失”。保存后释放工位，允许开始下一轮。

结束后在记录详情中追加复核。原始结论和截图保持不变；“复核确认异常”或“需要返工重检”会在结果旁明确显示。返工沿用原产品和工件编号，生成关联的新周期，重新进行两阶段检查。

当前使用现有单账户体系，每次人工确认均要求重新输入该账户密码。审计身份是登录账户，不是自由填写的姓名；共用同一个账户无法区分实际操作人员。本版本没有宣称具备独立质检员角色或多角色授权。

## 刷新 断流与保存失败

浏览器刷新、退出或服务重启不会删除已保存的周期。再次进入时恢复当前阶段，并要求人工核对工件与前序证据后继续，核对操作写入历史；相机或本地文件须重新打开。若工件已更换、前序证据不再适用或过程无法确认，应结束为中断后整站重检。服务不会自动推断中断期间发生的操作。

工位1同一时间只能有一个活动周期。重复提交同一请求返回同一结果；不同页面提交旧版本会被拒绝，须重新同步后核对阶段。保存失败不会推进阶段或显示最终通过。网络错误后，可在原确认窗口重新输入密码并重试，已提交的内容锁定、请求编号保持不变；若刷新页面，先查询已保存状态，避免误建新件。

## 数据与备份

周期与操作事件保存在现有数据库，截图独立保存在 `DATA_DIR/pilot-evidence/<周期ID>/`。本机默认数据库为 `.runtime/local.db`，截图目录为 `.runtime/local-data/pilot-evidence/`。截图写入、刷新到磁盘并改名后，阶段状态与事件在同一数据库事务提交；最终通过前再次核验两阶段截图的存在性和哈希。

备份须同时覆盖数据库和证据目录。SQLite 使用在线备份接口，或在 API 和 Worker 停止后复制数据库及相关文件；只导出 JSON 不包含截图文件。恢复时将数据库和证据目录放回对应位置，再启动并逐件核对历史记录。现有分析任务保留期清理不处理工位试点记录；此版本没有自动删除试点证据。

## 验证与后续接入

```powershell
npm run test:pilot
npm run test:pilot-ui
node tools/python.cjs tools/test-pilot-ui.py --registration-paused
```

后端测试覆盖阶段顺序、指定位置、唯一活动周期、请求去重、旧版本冲突、认证、文件及数据库写入失败、过期/缺失证据、重启恢复、复核与返工。原人工流程浏览器回归显式启用登记；`--registration-paused` 则以真实模型验证六工位F8直接检测、重复键拦截、视频自动归档、摄像头、零工件创建、刷新和手机布局，使用隔离数据库。视频默认使用本次用户提供的素材，可通过 `STATION_DASHBOARD_VIDEO` 指定另一个本地视频。这些流程测试不代表识别精度验收。

现场采集时先确认位置图、孔位可见标准和遮挡时间段，并录制完整正常流程与漏孔、漏螺丝、错序、拆卸等异常。后续接入两类模型时继续使用周期ID、版本冻结、证据保存及事件审计，并将自动结果与人工结果明确区分。
