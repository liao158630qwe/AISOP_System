更新日期：2026 年 11 月 10 日。适用项目：`D:/Project/AISOP`。本次整理与验证跨 11 月 9–10 日完成，历史训练日期按各运行记录保留。

本文根据当前配置、训练脚本、保留的数据集、实际训练日志和验证报告整理。工位 1 为螺丝安装视觉检测，工位 2 为贴条外观检测。历史版本用于解释训练过程；“当前规则”以本文第 1、6 节及当前配置为准。

## 1. 当前业务目标与合规条件

### 1.1 共同目标

摄像头连续观察一件工件，逐个确认标定位置。**本轮所有必检位置均取得稳定、正确的视觉证据后，服务器判定合规，工位页面自动结束本轮、归档并弹出“检测合规”。**

不同位置可以在不同采样帧中确认，不要求一帧同时看清全部位置。已确认位置被手遮挡、暂时离开画面或发生单帧漏检，不会直接清空本轮历史。新工件必须开始新轮次。

| 项目 | 工位 1：螺丝 | 工位 2：贴条 |
| --- | --- | --- |
| 当前权重 | `models/screw-head-v4b-yolo26m.pt` | `models/sticker-patches-v6.pt` |
| 当前配置版本 | `screw-video-v4b-yolo26m` | `sticker-appearance-v6-visual` |
| 检测对象 | 螺丝头、空孔 | 三角贴、方形/长方形贴、裸位 |
| 标定位置 | 原视角 12 处；俯视视角 11 处 | T01、T02 两处三角，R01–R06 六处方形，共 8 处 |
| 预装件 | 两个视角各含 2 处，必须确认 | 无单列预装件 |
| 单位置确认 | 默认 2 帧一致有效证据 | 当前 3 帧一致有效证据 |
| 合规条件 | 所选视角全部操作位置及预装件均确认有螺丝 | 8 个位置均确认存在预期形状贴条 |
| 是否必须看见安装前为空 | 否 | 否 |
| 是否核验操作顺序 | 否 | 当前规则不核验 |
| 外观之外的能力 | 不验证扭矩、紧固力 | 不验证胶粘强度，也未验收毫米级偏移 |

螺丝原视角的 12 处是“10 处操作位 + 2 处预装件”；俯视视角的 11 处是“9 处操作位 + 2 处预装件”。编号和数量依所选标定解释，不能在页面上固定写死为 12。

### 1.2 本次对贴条规则的调整

旧贴条规则要求每个位置出现“明确未贴 → 明确已贴”，并要求两处三角先于方形完成。因此，即使外观列表已显示 8/8，缺少贴前画面或无法证明先后，也可能显示证据不足。

按最新要求，当前配置明确启用 `verification_mode: visual-cumulative`：

1. 贴条只要在本轮得到各位置正确形状的稳定确认，即可累计完成。
2. 从已贴好的工件开始检测也可以通过，不必补拍贴前过程。
3. 三角和方形的观察先后不再阻止本轮合规。
4. 错形、明确未贴以及未确认位置仍按相应状态处理，不把“检测到任意东西”当作完成。
5. 旧冻结配置仍保留原来的顺序/动作规则，用于解释历史任务；本次不改写历史归档。

这次调整没有重新训练权重，也没有降低检测置信度阈值。配置版本增加 `-visual` 用来区分判定规则，网络权重仍然是 v6。

## 2. 两个模型共同采用的技术路线

两者都是“**工件定位 + 标定位置局部检测 + 多帧确认 + 本轮汇总**”，不是单纯把整张画面交给一个模型后直接给出合规结论。

```text
开始本件：创建独立轮次，清空上一件历史
  ↓
摄像头采样：保留帧身份、时间、工位和相机身份
  ↓
工件定位：将当前画面与参考标定对齐
  ↓
按必检位置裁剪局部区域，排除不可核对的区域
  ↓
YOLO 批量检测：类别、位置、置信度
  ↓
按位置匹配，转换为 PRESENT / EMPTY / WRONG / UNKNOWN
  ↓
时间窗口内多帧一致 → 更新该位置的本轮确认状态
  ↓
全部位置正确确认？
  ├─ 是 → 服务器 PASS → 结束本轮 → 归档 → 弹窗 → 等待下一件
  └─ 否 → 继续采样；手动结束/视频结束时给出最终未贴或证据不足结论
```

### 2.1 为什么采用局部区域

训练数据本身以螺丝或贴条位置附近的小图为主。线上也按同样的几何位置裁剪，使网络输入与训练样本相符，同时保留小目标细节。直接将这些权重绑定为整帧场景检测，会改变目标尺度及背景分布；此前工位绑定问题正是通过恢复定位和局部裁剪解决的。

局部检测仍需要把模型框分配到正确位置。邻近位置、反光、治具空孔和备用模板不能因为出现在同一画面中就被计入必检位置。

### 2.2 类别、位置与规则是不同层次

| 层次 | 螺丝例子 | 贴条例子 |
| --- | --- | --- |
| 模型类别 | `screw_head`、`empty_hole` | `triangle_patch`、`rectangle_patch`、`bare_site` |
| 标定位置 | S01、S02…… | T01、R03…… |
| 业务状态 | 某必装位有螺丝/明确空孔/未知 | 某贴位形状正确/明确裸位/错形/未知 |
| 本轮结论 | 所有必检位置确认后 PASS | 所有必检位置确认后 PASS |

网络并不直接学习“这是 S02 的第几道工序”。位置名称与预期类别来自配置；工件合规来自这些位置的确认结果。人体框和骨骼是同帧的辅助观察，不参与两个工位的外观合规判定。

## 3. 数据准备与标注原则

### 3.1 “视频全部正确”应如何使用

用户确认视频里的完整操作都是正确示范，可以用于确定正常工序和完成后的外观，但不能把视频的每一帧、每一个位置都标成“已安装”。安装前的空孔、贴前的裸位，是正常过程中真实存在的负类；手遮挡时则不能凭最终完成结果反推当前帧已安装。

每个位置至少区分：明确未装、操作过渡/遮挡、明确已装。过渡帧不强行赋予正负标签。不清楚的区域从监督训练样本中排除，在线则保持 UNKNOWN。

### 3.2 数据组织顺序

1. **确认完整轮次和来源**：保存视频名、SHA-256、画面方向、帧率与时长。
2. **建立参考标定**：确定工件主体、必检位置、位置编号、预期类别、预装件及不必装的背景孔位。
3. **按时间抽帧并对齐**：使用与生产检测相符的方向处理、缩放、JPEG 采样和局部裁剪。
4. **逐位置核对标签**：标注可见目标；明确遮挡、反光不清和贴放瞬间的排除区间。
5. **补全裁剪内邻近目标标签**：一个裁剪中出现多个目标时应共同标注；邻近目标状态不明时排除该裁剪，避免把真实目标当背景。
6. **划分训练、验证、测试**：优先按完整工件/轮次/视频划分，再在各集合内部抽帧。
7. **审计与冻结**：核对重复图像、来源时间、每位置正负样本数，并保存标签审阅图和清单。

### 3.3 样本数量的口径

“一张裁剪图片”“一个可判读位置观测”“一件独立工件”是三种不同单位。一次采样可能产生多个局部裁剪，同一位置在连续帧中也会反复出现。因此，数百张裁剪不能解释为数百件独立产品。

螺丝早期数据按同视频时间段划分，且参考图辅助了留出标签，属于开发数据。贴条 v6 改为按完整轮次划分，减少相邻帧混入不同集合的问题，但仍来自同一录像和机位，不能代表跨工厂、跨相机泛化。

## 4. 工位 1：螺丝模型的训练方法

### 4.1 任务定义和初始数据

初始素材为 `VID_20261017_103101.mp4`，历史记录为约 53.66 秒、3840×2160、1,612 帧。参考图中标出 12 处可见螺丝，其中 2 处为灯板预装件。

检测标签只有两类：

- `0 = screw_head`：明确可见的螺丝头。
- `1 = empty_hole`：明确可见的空孔。

初始标签由参考点、SIFT 对齐与模板匹配辅助传播，再通过局部图像复核。其性质是辅助标注，不能称为独立标注员逐帧复核的金标准。

初始数据实存为训练 172、验证 12、测试 42 张。历史时间划分为训练 5–26、32–36、41–46 秒，验证 28–30、38–39 秒，测试 49–51.1 秒。不同区间留出时间间隔，但共享同一产品和机位。

### 4.2 迭代过程及每一步解决的问题

| 阶段 | 数据与模型变化 | 训练配置 | 主要目的 |
| --- | --- | --- | --- |
| v1 | YOLO11n；172/12/42 张裁剪 | 120 轮，输入 192，batch 16，AdamW，lr 0.001 | 建立螺丝头/空孔局部检测基线 |
| v2 | 纠正真实空孔被辅助标成螺丝头的问题，剔除不明确标签；237/17/42 张；YOLO11s | 100 轮，输入 256，batch 16，lr 0.0006 | 优先修标签质量，补斜视及导线遮挡难例 |
| v3 | 使用同一份修正数据，从 YOLO26m 预训练权重训练 | 100 轮，输入 320，batch 8，lr 0.0006 | 提高压缩、轻微模糊条件下的识别能力 |
| v4 第一阶段 | 加入 `lv_0_20261017141529.mp4` 新视角数据，从 v3 微调 | 60 轮，输入 320，batch 8，lr 0.0003 | 适配俯视角度及新工件外观 |

最终混合视角数据集实存 **486 张训练、17 张验证、42 张测试**。历史报告记载包含 30 张安装前空孔难负例、120 张 S02 原始像素样本及 2 张标签纠错；这些 30/120 属于历史构建记录，当前总数已重新按文件核对。

S02 专项使用 73–79.5 秒的安装前后画面、不同裁剪偏移和原生分辨率尺度构建样本。晚段样本进入训练后，相应新视频验证/测试图从留出集合移出，最终 17/42 张留出裁剪来自旧视频；新视频的整段复测因此属于适配后的开发回归。

### 4.4 当前部署与历史描述的区别

早期历史文档写过“基础 v4 处理一般位置，v4b 仅处理俯视 S02”。**当前实际配置已经以 v4b 作为主权重，S02 的覆盖项也指向同一 v4b 文件。** 当前推理实现会复用该模型实例、将这些裁剪合批，避免重复加载和单位置重复调用。

当前螺丝定位使用 CUDA DISK 特征及几何匹配，分别核对原视角和俯视标定；训练资料中的历史辅助标注则使用过 SIFT/模板方法。不要把历史标注方法误写成当前在线定位全部在 CPU 上执行。

不同视角的本轮确认历史隔离。原视角与俯视视角同名编号不能直接拼接成一套完成证据。

### 4.5 已有验证能说明什么

历史同视频开发复核中，修正后的 v2 在 49 个已查看的可见螺丝位置上由旧流程 33 个检出提高到 49 个；9 个已查看空孔中 5 个正确识别、4 个未知，没有误报成螺丝。v3 对压缩/模糊合成压力样本有所改善，但并非所有指标都优于 v2，速度也并非全面更快。

这些结果包含已参与开发的数据和辅助标签，不是独立产品准确率。当前 v4b 仍缺乏覆盖各孔位的独立真实漏打成品测试，不能将早期裁剪 mAP 直接当作产线漏打检出率。

## 5. 工位 2：贴条模型的强化方法

### 5.1 当前训练对象

当前使用 YOLO26m **外观检测**，类别映射为：

| 类别 | 含义 | 配置对应位置 |
| --- | --- | --- |
| 0：`triangle_patch` | 三角贴片 | T01、T02 |
| 1：`rectangle_patch` | 方形或长方形贴片 | R01–R06 |
| 2：`bare_site` | 未贴的裸露贴合位 | 任意必检贴位 |

旧目录中的 `sticker-actions-*.joblib` 是另一条动作候选路线，当前工位 2 没有使用它来代替外观确认。当前配置也没有启用可选的 `material_model`。贴条形状由 YOLO 类别和位置预期共同核对。

### 5.2 v6 数据来源与轮次划分

强化素材为用户提供的 `C:/Users/Administrator/Downloads/贴条.mp4`，约 **347.99 秒、5 个操作轮次**。用户确认全部操作为正确示范。

| 轮次 | 用途 | 原因 |
| --- | --- | --- |
| 第 1 轮 | 旧素材回归 | 与既有素材重叠，不作为新的独立测试 |
| 第 2、3 轮 | 训练 | 提供实际安装前后及不同遮挡条件的样本 |
| 第 4 轮 | 验证与最佳权重选择 | 用于模型选择，不进入训练 |
| 第 5 轮 | 最终测试 | 在选好模型后评测，不用于训练 |

按 2 FPS 采样制作标注资料；每位置记录“最后明确裸位时刻”和“最早明确已贴时刻”，两者之间的过渡区域排除。该时间表仅用于离线标注，在线检测不读取这些秒数，也不会按录像时间自动生成已贴状态。

训练裁剪捕获自实际运行检测器的透视校正结果，并按 PNG 保存；裁剪前流程与当时浏览器的方向、缩放和 JPEG 采样处理相匹配。有效位置裁剪约 160×160，网络输入为 320。

### 5.3 遮挡与标签清洗

首先排除定位失败、主体锚点不符、手套/绿色遮挡及标签过渡区间。复核又发现暗色手臂、肤色和蓝色衣袖可能通过原有可见性检查，因此标注准备中增加颜色排除与人工指定遮挡区间。

第一次 `training-v6` 训练因此中止；清洗数据后，重新从原 v5 开始，形成有效运行 **`training-v6b`**。废弃运行没有作为最终权重。

标签由助手逐段辅助复核，不是独立人工金标准。旧模型预测用于寻找值得检查的帧，**没有直接作为此次新增监督标签**。

- 多帧确认可以减少短暂波动，但持续多帧的同类误判仍可能被确认，需要新增难负例和独立验证。

## 6. 实时判定逻辑：从单帧到“检测合规”

### 6.1 单帧状态

| 状态 | 含义 | 如何进入 |
| --- | --- | --- |
| PRESENT | 对应位置检出正确目标 | 类别、位置、置信度及可核对条件满足 |
| EMPTY | 明确检出空孔或裸位 | 检测到对应负类且达到负类阈值 |
| WRONG | 贴条形状与位置预期不符 | 检出另一种贴条形状且达到错形阈值 |
| UNKNOWN | 当前无法可靠判断 | 遮挡、未定位、低置信度、未检出或位置匹配失败 |

**没有检出目标不等于明确缺失。** EMPTY 必须有明确的空孔/裸位证据；UNKNOWN 不会被自动当作已完成。

### 6.2 当前关键门槛

| 设置 | 螺丝 | 贴条 |
| --- | --- | --- |
| 默认正类阈值 | 0.45；俯视 S03 配置为 0.30 | 0.55 |
| 负类阈值 | 空孔 0.65 | 裸位 0.75 |
| 错形阈值 | 不适用 | 默认 0.80 |
| 网络输入尺寸 | 320 | 320 |
| 位置分配距离 | 主配置 20；俯视 14 | 35 |
| 证据确认帧数 | 默认 2 | 当前 3 |
| 未完成证据最大相邻间隔 | 默认 2 秒 | 默认 2 秒 |
| 未完成证据窗口 | 默认 4 秒 | 默认 4 秒 |

位置距离使用各自参考标定的坐标尺度，不是毫米。置信度是模型分数，不是“现场准确率”。螺丝局部上下文、贴条主体锚点/可见性等检查仍参与是否采纳候选，这张表不意味着只比较一个分数即可完成。

贴条主体检查包括 3 个锚点，要求指定主锚点通过且至少 2 个锚点达到当前 0.5 门槛，避免把备用模板或正在移走的模板当作有效工件。

### 6.3 多帧确认与历史保留

确认采用有时间上限的证据窗口。螺丝通常需要 2 次、贴条需要 3 次一致有效观测。UNKNOWN 不投票；如果间隔或总窗口超限，尚未确认的候选重新累计。不能把相隔很久的零散候选凑成确认。

确认写入本轮历史后：

1. 遮挡、失去定位和 UNKNOWN 保留已确认状态。
2. 单帧相反结果不立即翻转确认。
3. 新的相反状态达到同样确认条件后，更新该位置。例如已贴位置被连续明确检测为裸位，会由 PRESENT 更新成 EMPTY。
4. 当前帧框只来自当前有效采样；历史确认条目不保留旧 bbox 来补画面。
5. 贴条历史独立于最近 120 帧的缓存。工件离开后，即使旧帧被滚动淘汰，也不丢失本轮确认。

### 6.4 判定表

| 情况 | 检测进行中 | 最终结束时 |
| --- | --- | --- |
| 所有必检位置均正确确认 | PASS，工位页面启动自动归档 | PASS |
| 仍有明确空孔/裸位 | 继续检测，保留未完成位置 | FAIL |
| 贴条确认错形 | FAIL；摄像头页面按异常结束处理 | FAIL |
| 仍有位置 UNKNOWN | 继续检测/等待新证据 | REVIEW，证据不足 |
| 工件遮挡，但本轮所有位置此前已确认 | 累计状态保留 | 无相反确认时仍按已有覆盖结果判断 |
| 新工件开始 | 建立新轮次，从未确认开始 | 不借用上一件结果 |

当检测中途已经齐全并自动归档后，后续画面属于轮次之外；系统不继续用下一件或工件移走后的画面修改该条归档。

### 6.5 采样缺口与“明明检测到了，却证据不足”

历史问题有三个不同原因：

- **规则问题**：贴条外观 8/8，但旧顺序规则缺少贴前或先后证据。当前累计外观模式已去掉该门槛。
- **缓存问题**：只用最近 120 帧重新汇总，工件离开后历史确认被挤出。已改为每轮持久确认历史。
- **链路问题**：曾有一轮在约 6.57–10.47 秒之间出现约 3.89 秒有效采样缺口，原 PASS 被连续证据保护降级。用户确认期间正常播放，该次缺口的全部根因没有被最终证明。

当前两工位返回明确的覆盖合同：`verificationMode=visual-cumulative`、必检总数、已确认数、操作位完成数、预装件确认数，以及 PASS 状态。只有服务器确认完整覆盖时，历史采样缺口不会再单独把它降为证据不足，缺口本身仍保存在记录中。

如果某个位置没有确认，仍不能因为列表数字、画面中出现过框或用户知道示范正确而强制 PASS。待确认位置仍需补足真正的视觉证据。

### 6.6 页面自动完成与设备接入

- **页面摄像头/图片**：新鲜且身份匹配的服务器结论触发结束，归档完成后弹窗；停止采样并释放本轮资源。
- **视频模拟摄像头**：当前累计视觉模式在完整 PASS 时也立即结束。旧动作/顺序任务仍按原回放终结逻辑处理。
- **后台采集器 + 工位页面**：页面收到新鲜的完整覆盖 PASS 后，提交一次持久化结束命令，等待采集器归档、释放及回执后弹窗。后台设备不会由浏览器直接删除检测流。
- **页面关闭/切走的后台采集**：采集器本身仍按原控制协议运行；本次自动结束触发位于正在监看的工位页面，不代表已实现无页面的 PLC 自动换件或后台自循环。

后台返回最终结果是归档依据。若结束阶段返回 REVIEW 或归档失败，页面保留该事实并提供原轮次的重试入口，不将此前的瞬时 PASS 当作已经保存成功。

## 7. 准确性优化与速度优化分别做了什么

### 7.1 训练层：改变模型识别能力

螺丝主要通过纠正空孔标签、补充难负例、加入俯视及 S02 原生像素样本，逐步训练到 v4b。贴条通过同机位新轮次、运行时一致裁剪、遮挡清洗和 v5 小学习率微调，训练到 v6。

本次汇总和规则调整期间没有再启动新一轮权重训练。此前贴条强化训练是真实 GPU 训练；螺丝本轮主要做的是既有权重的推理工程优化。

### 7.2 推理层：减少重复工作

| 优化 | 做法 | 作用边界 |
| --- | --- | --- |
| 螺丝模型复用 | S02 覆盖项指向主权重时，复用同一实例并合批 | 降低重复加载/推理，位置阈值与归属保留 |
| 贴条图像回传 | CUDA 张量转连续 HWC 后交给 OpenCV | 减少隐式整帧复制 |
| 贴条锚点处理 | 缓存参考灰度，仅校正锚点搜索局部区域 | 保留训练时的缩放、彩色校正、灰度顺序 |
| 贴条遮挡跳过 | 已被可见性检查排除的裁剪不进入 YOLO | 保持 UNKNOWN，维护原位置索引 |
| 检测框回传 | 合批后集中取回结果 | 减少逐目标传输与同步开销 |

这些变化曾在相同解码 JPEG 上做前后交替推理对照，829 个采样的定位、目标状态、事件/累计状态和最终结论保持一致。存在小幅浮点差异，不能表述为所有数值逐位相同。

### 7.3 工程提速的历史实测

本机 RTX 5070 Ti；每个视频按 4 FPS 完整采样；前后版本预热后对同一输入交替运行。下表贴条仍是当时的 **v5 权重**，与 v5→v6 的训练对照不是同一次实验。

| 视频 | 采样数 | 全程中位耗时 ms：优化前→后 | P95 ms：优化前→后 |
| --- | ---: | --- | --- |
| 螺丝 `lv_0_20261017141529.mp4` | 364 | 28.62 → 28.74 | 81.67 → 72.71 |
| 贴条 `lv_0_20261017162449.mp4` | 242 | 110.84 → 87.07 | 123.57 → 103.54 |
| 贴条 `lv_0_20261018150631.mp4` | 223 | 101.57 → 84.72 | 125.88 → 103.82 |

螺丝成功定位帧的中位耗时由 72.18 降至 63.37 ms，下降约 12.2%；全程中位数受大量未定位帧影响，没有改善。贴条首段全程中位耗时降低约 21.4%。

该计时包含检测入口与所需图像回传，不包含原视频解码/编码、人体分支、HTTP 和页面显示。不能用“单帧 80 多 ms”直接证明端到端稳定 10 FPS。

### 7.4 页面与状态管理优化

原视频层与检测样本层在开始阶段交替露出，会让人看到画面争抢。已加入检测模式的不透明承托层和等待状态，过期结果清除时不露出不对应的原视频画面；检测框仍绑定其真实采样。

这一显示修复、120 帧历史修复和本次自动完成规则，属于工程与业务层的改进，都不能记作模型训练准确率提升。

### 7.5 当前规则的真实浏览器验证

使用既有开发录像 `lv_0_20261017162449.mp4` 和真实 v6 权重，经过浏览器采样、JPEG、HTTP、GPU 检测和真实归档接口，在第 8 个位置确认后自动弹出“工位2 · 检测合规”。测量区间运行 47.4945 秒，接收 472 次成功结果，有效采样 9.938 FPS；HTTP、脚本和身份错误均为 0。视频停在约 47.44 秒，早于其 60.49 秒片尾。

采样到响应中位/P95 为 114.3/155.4 ms，服务器处理中位/P95 为 91.16/99.15 ms。使用独立临时数据库，未写生产业务记录。此项验证是已知录像的完整页面链路，不是物理摄像头或新增 347.99 秒视频的全片独立验收。详见第 10 节验证记录。

## 8. 如何同时评价准确性和速度

建议把验收拆成以下层级，不能只看 loss、mAP 或单次 PASS：

| 层级 | 应统计的指标 | 能发现的问题 |
| --- | --- | --- |
| 局部模型 | 各类别 Precision、Recall、混淆、框位置误差 | 空孔/螺丝混淆，裸位/贴片混淆 |
| 位置状态 | 各位置正确率、误报 PRESENT、误报 EMPTY、UNKNOWN 比例 | R03 提前误报、R05 难确认等局部薄弱点 |
| 完整工件 | 正确件误拒率、真实缺陷件漏放率、自动完成时间 | 是否因累计误报过早放行、是否迟迟不完成 |
| 摄像头全链路 | 成功采样 FPS、采样到响应 P50/P95、最长缺口、错误数 | 前端采样、编码、网络、队列、模型冷启动 |
| 多工位运行 | 各工位独立 FPS/P95、显存、身份隔离、归档一致性 | 并发排队、模型重复加载、跨轮次串状态 |

真实缺陷样本要按“位置 × 缺陷类型 × 工件”统计，尤其关注把缺陷误认为已完成的情况。改变累计规则后，还应重新检查“最后一个真实安装动作完成前是否提前 PASS”，不能沿用旧顺序任务的整轮准确率。

目标 10 FPS 是采样配置值。应同时给出测量区间、预热条件、实际成功采样数、HTTP 错误、页面可见性和是否有归档时间，而不是仅报告请求频率。

## 9. 下一轮训练建议

以下是后续方案，不是本次已经完成的数据收集或训练结果。

### 9.1 螺丝：优先补真实缺陷与困难视角

1. 逐必检位置录制最终漏装工件，明确区分应装孔、预装件和永久不用的孔。
2. 重点补 S02 小目标、S03 线缆遮挡、金属反光与空孔相似样本；清晰正例和清晰负例都需要。
3. 覆盖正常安装、安装前等待、操作遮挡、工件移走和空台，防止从治具推断完成。
4. 按独立产品/拍摄批次留出验证与测试；新视角样本一旦用于调参，不再称为独立泛化集。
5. 从当前 v4b 做小步微调，并同时回归原视角与俯视视角，避免专门优化一个位置导致其他位置退步。

### 9.2 贴条：先补 R03、R05、R06

1. R03 增加明确未贴但有阴影、暗色衣袖、边缘结构的难负例。
2. R05/R06 增加手离开后稳定可见的正确贴片正例，保证验证和测试中也存在这些位置的正样本。
3. 增加真实漏贴、错形和部分覆盖样本，并区分“看不清”与“真实缺失”。
4. 增加不同人员、手套、曝光及工作台扰动，按完整件划分集合。
5. 先检查标签和裁剪一致性，再试输入尺寸、轻量骨干或导出加速。所有速度候选都与当前 v6 做相同数据、相同阈值下的对照。

### 9.3 训练闭环

```text
线上误判记录 → 定位具体位置和源帧 → 核对标签与可见性
  → 加入有来源的难例 → 冻结数据划分 → 小步微调
  → 验证选权重 → 独立测试 → 完整工件时序回放
  → 实际摄像头和多工位性能检查 → 发布并保留回退资产
```

若需把“扭矩合格”或“胶粘强度”纳入最终质量标准，应另接可测量的证据并定义接口；仅增加当前外观模型训练轮数不能补出这些标签。

项目内命令通过 `node tools/python.cjs` 使用配置的 Python。先保存现有输出；旧训练脚本中部分路径固定，不能直接重跑准备步骤覆盖已有审计数据。

```powershell
# 从项目目录执行：只读核对现存配置、训练日志、数据数目和权重来源
node tools/python.cjs test-results/visual-coverage-20261109/audit_training.py

# 当前累计判定与归档回归；包含显式观察夹具，不是准确率测试
node tools/python.cjs -m pytest tests/test_sticker_history.py tests/test_stickers.py tests/test_station_terminals.py tests/test_transport.py -q

# 使用已冻结数据，从 v5 创建一个新的贴条微调运行；仅在需要再次训练时执行
node tools/python.cjs tools/strengthen-sticker-model.py train --run training-v6-recheck-new --epochs 30

# 对新候选依次执行验证、最终测试；这里的训练脚本沿用其冻结的历史评测配置
node tools/python.cjs tools/strengthen-sticker-model.py evaluate --model outputs/sticker-strengthening-20261109/training-v6-recheck-new/weights/best.pt --split validation
node tools/python.cjs tools/strengthen-sticker-model.py evaluate --model outputs/sticker-strengthening-20261109/training-v6-recheck-new/weights/best.pt --split test
```

网络类别识别、累计外观合规和旧顺序事件指标要分别记录版本。重新运行旧冻结配置的评测，不会自动变成当前规则的验收；当前摄像头行为应另外经过工位页面、HTTP、真实权重、归档和新轮次验证。
