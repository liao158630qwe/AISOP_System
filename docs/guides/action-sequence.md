# 通用动作顺序检测

服务器页面在“通用动作顺序”中默认选择“抬手 → 伸手 → 弯腰 → 移动（示例）”。适用于上传视频和实时摄像头。选择“仅观察动作”可关闭顺序检查。修改选项后重新开始检测。

每个步骤需要同一人物的可靠证据持续至少 0.5 秒；每步默认等待 30 秒。各人物分别累计进度，后续动作提前出现会记录顺序复核事件。缺帧会打断持续计时，超过 0.75 秒未获得可靠证据或人物关联不确定会重新累计流程。实时推理过慢时可能无法形成连续证据，应查看界面实际检测帧率。上传分析至少需要 2 fps。

重复相同动作步骤必须先观察到动作释放。当前每条轨迹完成一轮后保留结果，重新开始摄像头检测会建立新流；不自动统计连续生产周期。

模板位于 `config/action-workflows.json`，支持调整动作顺序、持续时间、等待上限和归一化人物中心区域 `roi`。`actions` 多值表示任一动作满足即可。创建任务时冻结配置及 SHA-256，后续修改模板不会改变已创建任务。已有示例视频并非四步流程的标注验证集。

实时 API：`POST /api/v1/realtime/frame?workflow_id=generic-actions`，JPEG 请求携带 `X-Stream-Id`（每次开始生成 UUID）及 `X-Frame-Time`（本次流起点以来的采样秒数，严格递增）。结束调用 `DELETE /api/v1/realtime/streams/{id}`。状态按登录凭据及流编号隔离，空闲过期或容量淘汰会建立新状态。响应中的 `streamEpoch` 标识状态创建时间。

输出 `actionSequence` 包含逐人物步骤、轮次和事件。离线分析在逐帧 JSON、回放页面和 HTML 报告中展示证据。`OUT_OF_ORDER` 表示后续动作先被观察到；`STEP_TIMEOUT` 表示等待超时；`CONTINUITY_RESET` 表示连续证据重置。

算法测试页不再用不同人物的三帧全局检出累计顺序。抓握候选与通用目标尚未可靠关联人物，因此这两类算法仅提供独立检出结果，不能确认个人顺序步骤。

当前动作分数来自骨架几何规则，`ActionDecoder.update(scores, t, valid)` 提供按秒平滑及持续确认接口；没有训练或验证过的时序神经网络。移动主要依据画面横向髋部位移，弯腰依据二维躯干倾角，镜头运动、视角和遮挡会影响结果。观察顺序完成不等于工序合格；未观察不等于漏做。

验证命令：`npm run test:api`、`npm test`、`npm run test:e2e`。端到端测试使用实际视频及姿态权重验证上传、回放、报告和实时接口；合成证据测试验证持续时间、人物隔离和遮挡，不代表真实动作准确率。
