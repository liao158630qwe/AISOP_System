# 灯具六工位检测配置与算法边界

本次以研究文档第3.1、5.5、7.2–7.6节为依据实现配置和算法基线。现场视频、专用权重和正式顺序尚未提供，用户已确认使用“未配置／待复核”。默认配置不生成合格结果。人体姿态模型仍负责人体和骨架，不能替代灯具专用检测。

## 页面使用

重启Web服务和Worker后刷新主页面。在“检测工位”中选择工位1–6，再上传视频或打开实时摄像头检测。选择框用于下一次检测，不改变旧任务。实时窗口展示该工位逐项检查结果；离线回放的工位检查区随采样帧更新，报告保留末次采样状态，JSON保留所有采样帧及冻结配置。未选择工位时保持通用人体姿态模式。

| 工位 | 对应检查项 | 本次算法接入 | 默认缺失依据 |
|---|---|---|---|
| 1 | 四个定位孔、四颗螺丝（两项） | 位置ROI＋模板匹配或专用YOLO | 8个现场ROI、模板或标注权重 |
| 2 | 五颗螺丝 | 逐位置模板或专用YOLO | 5个现场位置与资源 |
| 3 | 两颗螺丝及黄色卡扣（合为一项） | 螺丝模板/YOLO，卡扣HSV连通域/模板/YOLO | 3个位置、稳定照明与现场阈值 |
| 4 | 两颗螺丝 | 逐位置模板或专用YOLO | 2个现场位置与资源 |
| 5 | 接端子动作、八颗螺丝及顺序（两项） | 螺丝视觉候选；顺序规则可用事件回放验证 | 插接时序模型、锁止/电测、8个位置、正式偏序、工具记录 |
| 6 | 壳体吹净、装饰框总成吹净、线束端子连接、四颗螺丝（四项） | 螺丝视觉候选；时间区间规则可用事件回放验证 | 作用区域、供气及流量记录、完成标准、连接证据、4个位置 |

共六工位、十一项。接端子和吹净尚未从视频生成工艺事件；没有供气/锁止证据时，手势或气枪出现不确认完成。规则回放工具与视频检测是两个独立验收层，当前没有PLC/MES数据接入。

## 版本化配置

配置文件：`config/stations.json`。该文件由服务器维护，浏览器只选择工位，不能提交模型路径或伪造批准状态。编辑后运行：

```powershell
D:/Anaconda/python.exe tools/validate-stations.py
```

每个工位包含`id/name/version/approved/fixed_fixture/min_sharpness/checks`。初始`approved=false`、`fixed_fixture=false`。填写并现场确认固定相机和治具、完整位置及视觉基线后才设置为true，并递增版本。批准视觉配置仍不意味着产品通过SOP。

每个存在检测项定义`expected`和完整的`targets`。例如工位3要求`{"screw":2,"yellow_clip":1}`，需要配置两个螺丝位置和一个卡扣位置，不能只填写卡扣。每个位置的`roi`为完整分析画面归一化`[x1,y1,x2,y2]`，不能叠加视频裁切。首版同检查项的位置ROI不得重叠，以免一个目标重复占用两个位置。每工位最多64个位置、一个专用YOLO资源。

单个黄色卡扣位置的字段示意（坐标和阈值仅用于解释格式，不能直接用于产线）：

```json
{
  "id": "clip-A",
  "category": "yellow_clip",
  "roi": [0.1, 0.1, 0.2, 0.2],
  "method": "hsv",
  "hsv_low": [18, 90, 70],
  "hsv_high": [40, 255, 255],
  "min_area": 0.08,
  "max_area": 0.8
}
```

三种视觉方法：

- `hsv`：HSV阈值→形态学开运算→最大连通域面积比例。仅用于黄色卡扣候选，颜色不是安装质量证据。
- `template`：设置`asset`为`config/templates/xxx.png`及`threshold`，用灰度`TM_CCOEFF_NORMED`。模板必须有纹理，不能大于ROI；相机位置、尺寸和光照变化需要重新标定。不是尺度/旋转不变算法。
- `yolo`：设置`asset`为`models/lamp-parts.pt`、`class_name`为实际训练类别、`threshold`为验证集确定的阈值。在位置ROI内推理，训练与验证应采用相同裁切尺度。拒绝人体姿态权重及未包含指定类别的检测权重；现有`yolo11*-pose.pt`不能用于此项。

资源只能位于项目`models/`或`config/`。默认不下载或虚构专用权重。离线任务冻结配置内容、配置哈希及资源SHA-256，执行前后检查资源一致性。实时检测按当前配置构建快照，变化后重建专用检测缓存。

局部清晰度不足、未配置、模板无效或未检出均为`UNKNOWN/REVIEW`；命中为`CANDIDATE`，仍非安装完成。首版没有自动遮挡检测、工件配准或相机移动检测，必须保持固定工位。不能将不同采样时刻的可见螺丝集合直接合并为同一产品的完成记录。

## 工艺规则回放

`algorithms/process_rules.py`提供纯函数回放，不读写生产数据库，不发送设备控制。`tools/check-process.py`读取JSON并输出诊断报告：

```powershell
D:/Anaconda/python.exe tools/check-process.py work/process-trace.json --out outputs/process-check.json
```

输入顶层字段为`spec/attempts/cycle/checkpoint/coverage_complete`：

- `spec`：`version/approved/targets/programs/precedes/durations`。`programs`必须完整覆盖位置；`precedes`是前置边列表，校验未知位置及环；`durations`为位置到允许时长区间的映射。不得把位置数组顺序默认为正式安装顺序。
- `attempts`：每项具有`id/revision/cycle/target/program/result/start/end/verified/valid`。结果取`OK/NG/UNKNOWN`，起止为带误差的`[最早,最晚]`秒区间。只有已验证且属于相同产品、位置、程序的有效证据参与当前规则。
- `coverage_complete`：表示调用者已核验必要设备记录覆盖完整，不能从“视频播放完了”推定。当前无设备适配器自动提供此标志。

实现位置集合去重、尝试计数、前驱完成—后继开始区间比较、持续时间区间判断、同事件版本幂等与冲突检查、当前版本选择、显式失效排除、历史NG保留。相近时间但错产品或错程序不能完成步骤。缺日志、重叠时间区间、未批准或未到检查点不会自动通过。存在明确NG保持违反，必须通过有依据的修订/失效处理，不能仅靠后一次OK覆盖。完整返工失效传播、多视角物理操作去重、迟到水位线、持久inbox/outbox仍未实现。

输出带`mode=DIAGNOSTIC_REPLAY`。即使诊断为PASS，也只说明输入事件满足所给规则，不证明视频识别正确或整个产品质量合格。

## 验证与后续接入

测试覆盖六工位清单、HSV/模板实际图像处理、未批准与模糊画面拒识、位置数量约束、配置冻结、错序/时间不确定、同位置重复、产品/程序冲突、版本冲突与历史NG。浏览器端到端测试验证工位选择、上传与实时结果均显示同一检查清单。

尚需现场数据才能实施和验收：工具尖端检测、基准点配准、ByteTrack工具跟踪、插接/紧固/吹净因果分段模型、产品周期关联、PLC/供气/工具数据融合。下一步应先采集并标注真实位置及正常/遮挡/漏装样本，完成专用检测验证，再接入动作与设备事件。当前的合成图像和规则测试不能作为产线精度报告。
