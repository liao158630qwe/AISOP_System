# 集中大屏看板

打开 `/board`，或点击检测首页的“集中大屏”。默认直接联动工位检测流，无需建立工件；展示检测轮次、算法判定、确认进度和归档趋势。独立页面无额外构建、字体下载或外部 CDN 依赖。通过右上角按钮进入浏览器全屏，Esc 或该按钮退出。需要现有管理员账户；工位终端凭据不可读取全局数据。

## 展示与操作

- 实时数据：可见页面约每 1 秒请求 `/api/v1/board/snapshot?mode=detection&range=all`，单次请求超时 8 秒且不重叠。检测统计、工位状态、事件列表和 TOP 一起更新。后台标签页暂停请求、滚动及轮播，回到前台立即同步。
- 统计范围：顶部支持“总体 / 当日 / 指定日期”，默认总体，浏览器保存选择。总体累计所有日期的有效检测记录；当日随 UTC+08:00 零点切换；指定日期固定查询所选日。统计卡片、工位计数、告警、异常 TOP 和趋势统一切换，页面注明范围；切换不修改记录。回收站记录不计入任何范围。过去日期的工位卡片显示该日最后归档结果及有记录的工位数，历史告警不自动弹出。
- 断线恢复：请求失败显示断线标识，保留上次统计并将工位标为待连接。连续失败逐步延长重试间隔，约 3 / 6 / 12 / 24 / 30 秒并附少量随机延迟；尊重 `Retry-After`（最长 60 秒）。浏览器离线时暂停请求，网络恢复后同步；无权限或登录失效时需重新登录。超过 10 秒未收到快照的状态不再显示为在线。
- 演示模式：页面按钮或 `/board?demo=1` 开启，所有模拟数据均有标识。每 8 秒更新、每 24 秒产生演示告警，不写入业务数据。
- 三个画面：综合总览、工位监测、质量告警。可手动切换，或以 15 / 30 / 60 秒轮播。登录、统计口径对话框打开或页面隐藏时暂停轮播计时；底部告警提示不暂停轮播。
- 告警列表：按发生时间倒序，展示最新 100 条；自动滚动可暂停，鼠标悬停或键盘聚焦时暂停。尊重系统的减少动态效果设置。
- 底部告警提示：首次同步历史事件不会自动弹出，后续新事件排队展示。以页面右下角小卡片展示，不遮罩页面、不抢焦点，可继续操作看板。队列最多保留最新 50 条，超出部分提示查看记录；页面去重记录最多 2,000 个 ID。同一检测轮次的实时异常与最终归档异常使用同一事件 ID，避免重复计数。跨日清理旧提示，已消失的实时告警从待看队列移除。“我已知晓”只关闭本屏提示，不修改检测记录。支持关闭按钮和 Esc；预览按钮只演示提示。
- 趋势：支持小时、班次切换，鼠标悬停或键盘聚焦图表数据点可查看通过、不通过数量。总体将全部日期的相同小时/班次汇总，单日范围只汇总该日归档记录。无判定的时段断开曲线，不补造数据。
- 工位联动：点击卡片中的工位名称，在新页打开原检测界面，可按 F8 检测并查看工位记录。卡片标明现场摄像头、设备采集、视频联调或图片联调；旧记录没有来源信息时明确显示“来源未记录”。

## 每日历史

看板统计接口支持 `GET /api/v1/board/snapshot?mode=detection&range=all`、`range=today`、`range=date&date=2026-11-08`。省略 `range` 时保留接口原来的当日行为；页面默认主动请求总体。返回的 `range` 标明范围、日期和是否含实时轮次。不同范围独立缓存，删除/恢复记录后同步失效；跨零点当日切换、指定日期固定、总体继续累计。

在实时模式点击顶部“每日历史”，查看数据库中已结束的检测记录。默认选择北京时间当天并筛选“不合规”；若大屏已指定日期，则沿用该日期，“高级功能”的选择删除列表也沿用。可切换日期、工位以及“不合规 / 合规 / 待复核 / 全部”。全部视图先列不合规，再列待复核，最后列合规，同类按结束时间倒序。页面显示所选日期和工位的总数、不合规、合规、待复核数量与合规率，结论筛选不会改变这些汇总数。

历史以 **UTC+08:00 的结束日期** 归档，跨午夜的一轮只属于结束当天；仍在检测的轮次结束后再进入历史。服务重启或采集租约过期的未完成轮次记为中断、待复核，不当作合规。旧数据缺少结束时间时按开始时间归档。因此每日历史的已归档总数可能与大屏包含当前运行轮次的总数不同。

“查看详情”显示最终结论、原因、算法原判、人工复核、起止时间、检测任务及来源。有效人工复核优先决定最终结论，原始算法证据继续保留。记录来自已有的 `station_inspections` 持久化数据，刷新页面或重启服务后仍可查询；服务器需按部署说明持久化数据库。

“删除”经确认后将该轮移入回收站，历史列表、工位记录和看板统计会同步排除；在“回收站”中可查看并恢复。删除不会停止正在运行的检测，也不会物理移除原始结果或关联告警录像。录像仍按独立的留存规则管理。演示模式不能操作真实历史，工位终端凭据不能访问全局历史。

接口使用当前登录会话，修改操作校验 CSRF：

- `GET /api/v1/board/history?date=2026-11-08&stationId=station-2&verdict=FAIL&limit=20&offset=0`：按日分页；`stationId` 可省略，`verdict` 为 `FAIL / PASS / REVIEW / ALL`，`deleted=true` 查询回收站。
- `GET /api/v1/board/history/{stream_id}`：详情。
- `DELETE /api/v1/board/history/{stream_id}`：移入回收站。
- `POST /api/v1/board/history/{stream_id}/restore`：恢复。

## 高级功能：选择删除与清空测试记录

在大屏右上角连续双击“高级功能”打开弹窗（按钮不显示“双击”提示；单击不打开；键盘聚焦后可快速连按两次 Enter 或空格）。默认进入“选择记录删除”：按归档日期（UTC+08:00）、工位、检测结论和检测历史/回收站筛选，勾选一条或多条已结束记录，支持全选本页、跨页选择，每次最多 200 条。切换筛选或刷新列表会清除选择。点击“删除所选记录”后核对完整所选清单、勾选永久删除确认并输入当前管理员密码，再提交删除。确认期间固定筛选和所选范围；只有所选轮次仍在运行或占用有效采集租约时拒绝删除，其他正在检测的轮次不受影响。

切换“清空全部数据”可查看当前账号下六个工位、所有日期的检测记录数量、回收站数量和运行状态。输入“清空全部检测数据”和当前管理员密码后，点击确认按钮执行永久清空。两种删除方式均会移除对应记录及其中的人工确认，更新统计、趋势、违规告警、每日历史和回收站。当前浏览器内对应记录的确认队列也会清理，并通知同源打开的检测页面。

此功能保留账号、工位与相机配置、模型、训练数据、独立保存的告警录像，以及原人工工件流程的数据。删除的检测记录无法通过回收站恢复。演示模式和工位终端不能执行；清空全部数据时，有未结束的检测或有效采集租约会拒绝清空。清空范围在预览后发生变化时，需刷新范围再确认。网络中断时不自动重发删除，请取消确认并刷新列表或清空范围核对服务器结果。

接口为 `GET /api/v1/board/reset`（预览）及 `POST /api/v1/board/reset`（提交预览版本、确认文字和密码）；验证管理员会话、CSRF 和密码后，在一个事务中删除记录。工位锁顺序与检测启动一致，清空操作不会删除预览之后新建的轮次。不会清空其他账号的记录。

选择删除复用 `GET /api/v1/board/history` 列表，通过 `POST /api/v1/board/reset/selected` 提交 `streamIds`（1–200 个 UUID）、`confirmation: "删除选中检测记录"` 和 `password`。管理员、CSRF、密码、记录归属及运行状态验证全部通过后才在一个事务中删除；混入其他账号记录会整批拒绝。返回 `deleted`、`alreadyDeleted` 和 `streamIds`；重复提交相同 ID 只会报告已删除，不影响后来新增的记录。

## 原界面完整操作

在首页选择工位，首次配置检测模型，开启摄像头或选择视频后按 F8。检测页和大屏共享同一条工位检测流；模型异常会同时进入检测页告警区和大屏。视频播放结束自动归档，也可手动“结束并归档”；“停止本轮”记录中断并待复核，不自动转为通过。再次按 F8 创建新轮次并清除上一轮的累计结论。

“查看工位检测记录”支持分页、展开结果及导出完整 JSON；历史结果按工位、轮次和输入来源核对。大屏当日轮次包含联调记录，不代表生产件数，也不代表模型准确率。大屏按约 1 秒轮询，服务端快照缓存 1 秒，显示延迟应实测，不能用单帧推理时间代替。

首页“详细分析报告”展示打开时的本轮结果快照，并可导出；“系统运行详情”显示服务检查、工位采样和启动条件。离线分析服务异常时仍保留诊断信息，便于区分服务问题与当前检测状态。

首页检测的图像编码使用独立浏览器 Worker，避免实时大屏刷新挤占主线程编码调度。采样仍只保留一个在途请求，不累计旧画面；页面隐藏时暂停采样，恢复后由后端记录采样缺口。现场长期采集应保持检测页面可见，或使用独立采集程序。

## 统计口径

时间为 UTC+08:00 自然日。每条工位检测流记一轮，包含当日开始、当日结束和仍在采集的跨日轮次；每帧不重复计数。真实视频回放检测也会计入检测轮次，该口径不代表实际生产件数。

已结束轮次读取 `station_inspections` 的最终结果；本轮使用有效期内的实时判定。过期、未完成、中断的轮次记为待判定。采样缺口阻止自动通过，但已检测到的明确异常仍保留 FAIL，与检测接口判定一致。`检测轮次 = 合规 + 异常 + 待判定`。归档交接按流 ID 去重，实时 PASS 不等同最终归档 PASS。

采样在线与算法结论分开显示：即使仍在等待确认，也显示在线和有效帧率。卡片展示实际检测任务、相机标识及确认位置数，例如“待确认 · 5/11 已确认”。停止后标记离线，保留“上轮合规”等归档结论，避免将历史 PASS 冒充当前检测。终端地址为 `/terminal`，已删除工件关联入口，默认直接按检测轮次运行。

检测合规率为 `PASS / (PASS + FAIL)`，包含本轮实时判定，待判定不进入分母。趋势只用当日已经结束的归档轮次，按结束小时分桶；班次固定为 00–08、08–16、16–24。无已判定数据时显示“—”。

告警与 TOP 包含当日算法归档 FAIL 和当前实时 FAIL，不依赖工件关联。一个检测轮次只计一次；类型按原因关键词匹配，一个事件可属于多类。没有真实异常时，告警与 TOP 保持 0。

原工件生产统计作为兼容接口保留：`/api/v1/board/snapshot?mode=production`（接口未传 mode 时也使用此口径）。检测大屏不再使用它，没有删除工件、人工记录或既有检查流程。

## 性能与服务器运行

检测轮次在 SQL 中按工位、判定和小时汇总，最新记录最多投影六行必要标量，不把完整逐帧 JSON 载入 Python。告警最多返回 100 行，TOP 统计整天数据。六工位实时状态批量读取；前端只替换发生变化的卡片和图表。

服务端按所有者和统计模式隔离缓存，完整快照缓存 1 秒，最多保留 8 个缓存项。检测模式在构建快照时同步刷新统计；兼容生产统计仍缓存 15 秒。并发刷新共享一次构建；等待超过 250 毫秒返回 503 和 `Retry-After: 2`。数据库失败明确返回错误，不把旧数据标成刚更新。鉴权先于缓存访问。

沿用 [服务器部署说明](server-quickstart.md) 的 PostgreSQL、HTTPS、独立 Worker 和持久卷配置。**当前 API 保持 1 个进程、1 个实例，不增加 `uvicorn --workers` 或 API 副本数**：工位采集流、时序推理状态和缓存保存在进程内。离线 Worker 与 API 分开运行，但并发增加仍须按实际 GPU 资源验收。

升级已有服务器时，在停止采集和安排维护窗口后执行：

```sh
docker compose build init api worker
docker compose stop api worker
docker compose run --rm init
# 上一步成功后启动；失败时先处理初始化错误
docker compose up -d api worker web
docker compose ps
docker compose logs --tail=100 api worker
```

初始化会幂等补建工件最新周期、当日开始/结束、事件时间、检测归档等索引，不改写业务数据。大表首次建索引可能等待或占用数据库写锁，因此应预留维护窗口。首次安装仍可执行 `docker compose up --build -d`。应用静态资源自带版本号，更新后刷新大屏。

每日历史升级还会创建 `station_inspection_deletions` 删除标记表和按归档日期查询的索引，适用于 SQLite 和 PostgreSQL；沿用以上初始化步骤即可。

登录后检查 `/api/v1/board/snapshot` 的六工位、`statisticsAt`、`Server-Timing`；在 `/api/v1/metrics` 的 `board` 字段查看 `hits`、`builds`、`failures`、`busy`、`lastBuildMs` 和缓存容量。快照禁止 HTTP 缓存。服务器长期运行验收应同时观察检测吞吐、大屏请求、数据库时延和告警恢复，避免只根据页面打开成功判断性能。
