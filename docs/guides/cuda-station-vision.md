# 工位 CUDA 图像处理

2026-11-07 的改动覆盖当前启用的多视角螺丝、贴条动作和 YOLO 人体检测流程。模型推理之外，服务端 JPEG 解码、缩放、定位特征、特征匹配、单应性估计、ROI 透视变换、模板相关性、前景提取和动作 HOG 特征改为 CUDA。

接口、权限、数据库、流调度、时序判定和小规模坐标输出仍由 CPU 处理。浏览器/采集器的原始视频解码与 JPEG 编码不属于这条服务端 CUDA 管线。旧版螺丝算法、贴片外观模式、可选 RTMLib 与算法实验面板仍有 OpenCV 图像处理；不能把系统描述为“所有代码全部在 GPU 上执行”。当前工厂使用的螺丝和贴条动作配置采用新的 CUDA 管线。

## 部署

- 使用 CUDA 版 PyTorch / torchvision。已验证环境为 PyTorch 2.8.0+cu128、torchvision 0.23.0+cu128、Windows、RTX 5070 Ti 16GB。
- 安装 `requirements-worker.txt`，新增固定版本 `kornia==0.8.3`、`kornia_rs==0.1.10`。不要为了安装依赖替换为 CPU 版 Torch。
- 部署 `models/disk-depth-v1.pth` 及其 provenance、LICENSE 文件。权重随当前螺丝/贴条任务快照一起校验；缺失或变动会阻断任务，禁止静默退回 CPU 定位。
- DISK 特征网络和 YOLO 使用 FP16；动作分类保留原训练特征契约和 CUDA FP64 概率计算，匹配和几何估计保留浮点精度。
- 专项槽位采用独立 CUDA stream；共享人体模型通过 CUDA event 处理跨流依赖。各工位的历史证据仍独立保存。
- 模型计时使用当前 stream 的 CUDA event，调用同一 Ultralytics 推理与后处理，避免默认性能计时器每个阶段同步整张 GPU，造成其他工位等待。
- 每个模型槽位使用固定执行线程，保留该线程的 CUDA/cuDNN 缓存，避免模型在线程间迁移后再次出现秒级首次执行停顿。线程有界且繁忙时拒绝入队。
- 正式检测前，应预热所有模型副本及标定图。只预热视频第一帧，可能没有触发定位后的 ROI 模型，首个有效画面仍会较慢。

本地启动器支持 `.runtime/local-settings.json` 的 `inference` 对象，只接受设备、并发池、姿态后端和线程数配置；不接受数据库或用户身份覆盖。修改后通过 `tools/restart-local.ps1` 生效。

`/api/v1/metrics` 中 `inferenceRuntime.stationVision` 声明迁移范围；同一接口可检查模型池容量、CUDA 设备与实际加载状态。`nvidia-smi` 用于观测整卡利用率，不代表某一个请求独占该利用率。

## 结果边界

定位由 OpenCV SIFT 换成 DISK 特征与 CUDA 鲁棒估计。这是算法变化，不是完全相同的算子搬迁；必须重新计算参考特征，不能混用旧 SIFT 描述子。分类模型、业务阈值及动作顺序规则保持原配置，但逐帧定位和可见目标可能发生变化。

测试包括 OpenCV 图像算子数值对照、带离群点几何恢复、空特征处理、原有分类概率回归、真实视频对照、六路并发和大屏联动。正样本最终 PASS 不能换算成准确率；缺少独立标注的漏装、遮挡、错序与空工装数据时，不能宣称召回率或误报率已达标。贴条动作样例仍存在动作证据缺失，详见本次实测报告。

本机性能不能当作双路 Xeon 6148 + RTX 4090 服务器的实测值。部署到目标服务器后仍需按真实六台相机来源验证端到端延迟和结果间隔。

DISK 权重来源和 SHA256 记录于 `models/disk-depth-v1.provenance.json`，上游许可证为 Apache-2.0。HOG 兼容实现按 OpenCV 4.11 的特征定义实现，用原 OpenCV 描述子做数值回归；未重新训练动作分类器。
