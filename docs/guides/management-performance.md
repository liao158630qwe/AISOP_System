# 训练与场景管理：服务器运行说明

更新日期：2026-11-06。适用于 `/training`、`/admin` 及其管理接口。

## 训练列表与任务状态

训练概览统计当前账户的全部任务。列表每页 25 条，按创建时间和任务 ID 稳定排序；工位、状态与名称/编号搜索在数据库执行，可以查到 100 条以外的历史。`GET /api/v1/admin/training-runs` 支持 `limit`（1–100，默认25）、`offset`、`search`、`station`、`status`，返回 `items/total/counts/has_more`。`items` 只含列表摘要，训练类型使用 `task` 字段；完整 `recipe/policy/audit/card/evaluation` 由任务详情或报告下载接口提供。依赖旧列表完整字段的客户端需要同步更新。

页面只有可见时自动同步：有排队/运行任务时约3秒一次，空闲时15秒一次；失败后指数退避到最多60秒。请求完成后才安排下一次，刷新/筛选会取消过期请求，搜索防抖300毫秒。详情只有打开后才请求，活动任务只在版本变化时更新；工作器日志仍按需读取最近64 KiB。

读取接口不再执行租约恢复写入。训练工作器领取任务前负责回收过期租约；如果所有 Worker 均停止，页面保留最后持久化状态，恢复 Worker 后再判定失联任务失败。浏览器关闭不影响训练任务。训练结果仍通过租约令牌防止取消或过期进程提交。

## 模型和场景目录

`GET /api/v1/admin/catalog` 使用一次关联查询读取同一数据库快照中的模型和场景。模型元数据在 `models` 中只返回一次，`scenes` 使用 `model_id` 引用；同一模型在一次目录请求中只做一次文件就绪检查。公共场景列表也已消除逐场景重复查询。编辑仍使用 revision 防止覆盖；发布时在短事务内锁定并重新检查关联模型，防止文件校验期间模型已停用却仍发布成功。

场景卡片和模型表格每页渲染20条，关联数量预先索引。管理目录目前仍一次读取当前账户的全部模型和场景，以支持全局筛选和编辑器选择；本次优化没有把它改成服务器分页。若未来达到数万场景或超大类别映射，应进一步拆分目录摘要、详情和服务器分页，并在实际数据量上测量。

服务器文件候选扫描缓存30秒，避免多个窗口反复递归遍历训练输出目录；新复制到 `models/outputs/model-imports` 的文件最多等待30秒。已注册模型按账户实时查询，不使用此缓存。文件使用前仍重新验证，缓存不表示文件可直接信任。

每个 API 进程同时只允许一个模型元数据加载，其余请求返回429和 `Retry-After: 3`，避免并发导入加载多个大型模型挤占内存；已提交成功的幂等请求仍可复用结果。客户端保留相同请求编号后重试。此限制覆盖模型加载阶段，不是上传带宽或磁盘配额。

## 部署与资源配置

训练实际使用 CUDA GPU，通过独立子进程和数据库单任务槽执行。独立进程不会隔离GPU算力，与现场检测共用一张卡时仍会竞争。`TRAINING_GPU_MEMORY_FRACTION` 默认0.25，只约束训练进程的 PyTorch 显存分配，不是算力限额，也不包含其他进程。CPU主要用于数据加载、预处理和服务逻辑。

优先在GPU有余量的时段训练；多GPU部署可通过 `TRAINING_DEVICE` 和 `INFERENCE_DEVICE` 选择不同的可见GPU。当前 Compose 为服务申请一张卡，使用不同设备前还需调整容器可见设备，不能只把索引改为 `cuda:1`。训练和检测必须使用同一套注册数据、数据库及同路径共享存储。

升级步骤：

1. 停止新训练提交，安排正在运行任务的维护窗口。
2. 保留原数据库及 `DATA_DIR`。执行 `python -m backend.init_db`，为现有表补建训练历史及租约查询索引，不删除记录。大表补建索引可能持锁，应在维护窗口完成。
3. 同步部署 API、Worker 与 `frontend/`，避免新页面请求旧接口。当前实时状态保存在 API 进程内，继续使用单 API 进程、单实例。
4. 容器环境按服务器运行指南重新构建，并确认 init 成功、API ready、Worker 运行、数据挂载一致。
5. 用真实模型和六工位负载分别验收“仅检测”和“检测＋训练”的推理P95、队列等待、显存峰值及失败率，再确定训练窗口和设备配额。

本次还运行了隔离的真实CUDA浏览器链路：`tools/test-training-ui.py` 完成特征训练、视觉训练及未达标拒绝、持久化和移动端检查；`tools/test-scene-management.py` 完成真实模型导入、ROI、发布/停用、视频Worker、快照历史和摄像头推理。测试数据写入独立数据库，不进入日常模型库。
