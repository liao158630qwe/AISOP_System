# SOP 与动作时序模型：公共数据集筛选及训练路线

核查日期：2026-10-10（北京时间）。用途：用户已确认先做研究和模型验证。

建议先用 **HA4M／IKEA ASM 验证装配动作时序模型，再用 Assembly101 扩大步骤分段实验，使用 IndustReal 验证步骤完成和执行错误**。MECCANO 适合补充螺丝刀、螺丝及零件交互。当前项目的五类人体动作和灯具工序需要各自的标签头，不能把公共装配标签直接改名后混在一起训练。

本次已核查官方网页、仓库和下载入口，并实际下载、解析两套小型标注包。**未下载完整视频、未启动模型训练、未产生准确率或替换在线模型。** 入口返回 HTTP 200 只表示网页可读；下文单独说明数据文件的实际获取状态。

## 2. 数据集比较与获取状态

### A. HA4M：最适合低成本装配骨架基线

- **内容：**41 名参与者、217 段装配视频、12 类装配动作；官方 README 给出 4,123 个动作标注，包含重复动作与 `don't care`。装配对象为行星齿轮机构，有取放零件、放置螺丝、使用内六角扳手等动作。
- **模态：**RGB、深度、红外、RGB与深度对齐图、点云、32 点 Kinect 骨架。每段含 `Labels.txt`；人工标注动作开始和结束帧。
- **建议训练：**先以原生骨架训练独立的 12 类因果 TCN，与小型因果 Transformer 比较；`don't care` 单独按官方定义处理，不转换为站立。再用 RGB 提取项目同版本 YOLO 特征，评估从传感器骨架到实际视频检测骨架的差异。
- **适配限制：**32 点 Kinect 骨架与本项目 17 点二维骨架的关节定义、置信度和分布不同；不能直接填入现有 74 维输入。全身姿态相近的装配步骤还需要零件及手部外观。
- **获取／许可：**官方 GitLab 与 README 可读，CC BY 4.0；全文多模态约 **4.1 TB**，不建议全量下载。优先从官方入口选骨架＋标签；本次尚未测量该子集体积或下载其实际文件。CNR 入口会扩充新数据，复现实验宜固定 Science Data Bank 的论文对应版本。
- **来源：**[论文](https://www.nature.com/articles/s41597-022-01843-z) · [官方仓库](https://baltig.cnr.it/ISP/ha4m) · [下载与标签说明](https://baltig.cnr.it/ISP/ha4m/-/raw/master/README.md) · [论文版本数据 DOI](https://doi.org/10.57760/sciencedb.01872) · [CNR 数据入口](https://cloud.cnr.it/owncloud/index.php/s/j5BZvG1sXPzh6x1)。

### B. IKEA ASM：最贴近固定工位相机的装配动作识别

- **内容：**371 次家具装配、48 名参与者、33 类动作，3 路 RGB、1 路深度，含动作边界、人体姿态、部件分割和跟踪。一次装配的多个视角不应算作多个独立人员／会话样本。
- **建议训练：**先下载动作标注与一个固定 RGB 视角，做 RGB 特征＋TCN／Transformer；再增加骨架分支，对比“仅骨架”和“RGB＋骨架”。对固定相机装配现场，其视角比纯第一视角数据更接近。
- **适配限制：**动作是家具部件与操作的组合；并非灯具工艺完成标签。官网说明人体姿态与物体标注仅约 1% 帧为人工标注，其他帧提供伪真值，不能当作全部人工真值评估姿态质量。动作边界为另一类标注。
- **获取／许可：**CC BY-NC 4.0，适合当前非商业研究；代码 MIT 不等于数据 MIT。Google Drive 提供动作标注、各模态分包。动作标注的文件页面实际可访问；本次未下载该压缩包。仓库所列视频数据约 **240 GB**，这是相应视频包的量级，不是本次实测所有模态总大小。
- **来源：**[官网](https://ikeaasm.github.io/) · [官方代码与分包](https://github.com/IkeaASM/ikea_asm_dataset) · [动作标注包页面](https://drive.google.com/file/d/1SwBNLViktSpk99jhh3sMXVGTMVr6tpju/view) · [完整目录](https://drive.google.com/drive/folders/1xkDp--QuUVxgl4oJjhCDb2FWNZTkYANq)。

### C. Assembly101：时序分段主数据集，也能做流程错误检测

- **内容：**官网口径为 4,321 个多视角视频、101 种玩具车，8 个固定视角＋4 个第一视角；下载说明对应 362 次录制。超过 10 万个粗粒度、100 万个细粒度动作片段，含手部姿态。粗粒度标签有 202 类，适合 Temporal Action Segmentation。
- **流程价值：**操作人员没有被要求遵循唯一固定顺序，存在自然顺序差异、错误和纠正。错误标注覆盖 328 条装配序列，含 `correct`、`mistake`、`correction` 以及错序、错位置、无必要拆卸等备注。合理的顺序变化不应一律标成违规。
- **建议训练：**先用单个固定视角的官方 TSM 2048 维特征＋粗粒度标注复现离线分段；官方提供 C2F-TCN。之后加入错误检测任务。RGB／手物交互特征比单独全身骨架更适合区分相似零件操作。
- **实时限制：**官方 TSM 使用 8 帧输入；下载特征和原版 C2F-TCN不能自动视为在线因果方案。即使上层 TCN 使用因果卷积，前级特征若使用未来帧仍会泄漏。实时实验需审计特征时间支持范围，必要时重提只依赖过去的特征。
- **时间单位：**通用动作标注说明指出原视频 60 fps、动作帧号按 **30 fps** 标注。错误标注仓库把边界称作 timestamps，但其 README 未单独明确单位；本次保留原值，转换秒数前核对对应视频及基线代码。不能把整数 7257 当作 7257 秒。
- **获取／许可：**2026 年 5 月官方迁移到 Hugging Face；仓库为 `gated=auto`，未登录读取文件返回 **401**。需要使用本人账户在官方页面取得访问权限后下载。API 元数据可读不表示文件免登录。CC BY-NC 4.0。HF 元数据报告占用约 3.89 TB，仅作全库量级参考，单视角视频／特征包大小需获权后查询。错误标注 GitHub 公开，本次已下载。
- **来源：**[官网](https://assembly-101.github.io/) · [当前数据入口](https://huggingface.co/datasets/cvml-nus/assembly101) · [下载说明](https://github.com/assembly-101/assembly101-download-scripts) · [时序分段基线](https://github.com/assembly-101/assembly101-temporal-action-segmentation) · [动作标注说明](https://github.com/assembly-101/assembly101-annotations) · [错误标注](https://github.com/assembly-101/assembly101-mistake-detection)。

### D. IndustReal：最接近“动作发生”与“步骤正确完成”的区别

- **内容：**27 名参与者、84 段第一视角维护／装配视频，包含 RGB、手部、视线、头部姿态等。RGB 为 10 fps。提供动作识别 AR、装配状态检测 ASD、步骤识别 PSR 的标注及基线。
- **关键标注：**`AR_labels.csv` 标动作区间；`PSR_labels.csv` 标步骤完成帧；`PSR_labels_with_errors.csv` 包含错误执行；`PSR_labels_raw.csv` 将组件状态标为 -1 错误完成、0 尚未完成、1 正确完成。**完成时间点不应未经说明变成整个动作的起止区间。**
- **建议训练：**RGB／物体状态编码器→步骤完成模型→流程核对，报告步骤识别、错误检测和完成时刻偏差。保留官方 train/val/test；部分错误只出现在验证／测试集，适合研究对未见错误的泛化，不能把这些错误调入训练后仍宣称未见错误测试。
- **适配限制：**第一视角与固定监控机位有差异；其装配成功定义不能替代灯具端子锁止、电测、扭矩或气流结果。
- **获取／许可：**数据页与代码明确 Apache 2.0。**2026-10-10 实查 4TU 数据站公告：文件上传下载暂停维护，预计 2026-10-11 左右恢复；这不是已恢复承诺。** 目前可读元数据，不能据此声称视频已经下载或可马上开训。无需阻塞其他数据集研究。
- **来源：**[官方仓库](https://github.com/TimSchoonbeek/IndustReal) · [数据版本与维护公告](https://data.4tu.nl/datasets/b008dd74-020d-4ea4-a8ba-7bb60769d224)。

### E. MECCANO：螺丝刀、螺丝和零件交互的补充数据

- **内容：**20 名参与者装配玩具摩托车，RGB／深度／视线；61 类动作、12 类动词、20 类对象，8,857 个动作片段。官网多模态版本 RGB 为 12 fps，带动作区间与手／物体框。
- **本次实查：**动作压缩包已下载并通过 ZIP CRC 校验；train／val／test 分别 5,057／977／2,823 段，11／2／7 个视频，视频 ID 无跨分区交集。
- **贴近灯具的原始标签：**`take_screw`、`take_screwdriver`、`align_screwdriver_to_screw`、`screw_screw_with_screwdriver`、`plug_screw`、`align_objects`。适合工具与零件交互表征，不直接等于某孔位锁付完成。
- **适配限制：**标注包是动作片段表，行顺序并非时间顺序，且动作有重叠。做连续时序训练前需按视频和起点整理，保留重叠并明确损失／评测口径；不能直接强制生成互斥逐帧真值。视角偏移仍需验证。
- **获取／许可：**动作标注可直接下载；视频和其他模态入口在官网。本次已读官网／README 未发现清晰的数据许可证，故登记为“许可待核实”，未凭公开可下载推定可自由再发布或训练用途范围。
- **来源：**[官网及全部分包](https://iplab.dmi.unict.it/MECCANO/) · [官方代码](https://github.com/fpv-iplab/MECCANO) · [动作标注 ZIP](https://iplab.dmi.unict.it/sharing/MECCANO/MECCANO_action_annotations.zip)。

## 4. 推荐执行顺序

### 第一步：建立小规模可复现动作基线

选择 HA4M 的骨架＋标签，先取覆盖训练／验证／测试人员的少量完整会话验证数据链路，再扩大到论文版本。若数据分发对逐模态下载不便，可用 IKEA ASM 的单固定视角＋动作标注建立 RGB 特征基线。

1. 先固定数据版本、下载清单、原始文件哈希和许可记录；不直接执行旧仓库的一键安装脚本覆盖当前项目环境。
2. 按原始数据集标签训练独立分类头。HA4M 可从 12 类开始；当前项目五类动作另外标注并微调。工序标签不是人体动作标签的互斥替代品。
3. 先划分人员／完整会话，再产生窗口；同一录制的多视角、重复片段、滑动窗口必须在同一分区。为论文可比性保留官方切分；额外做更严格的跨人／机位切分时独立命名与报告，不悄悄改变官方协议。
4. 骨架模型首轮复用 10 Hz、64 点窗口思路。输入维度按来源 FeatureSpec 显式配置；避免把 32／25／手部关节强行映射成完整 COCO17。若缺少面部等关节，不能编造有效观测。
5. 比较固定输入与预算下的因果 TCN／小型因果 Transformer。公共单标签动作头与项目多标签五动作头使用不同损失；项目重叠动作采用带审阅／可观测性掩码的 BCE。

### 第二步：加入 RGB、对象与长时步骤关系

对 IKEA ASM 或获权后的 Assembly101，先用冻结视觉特征训练小型时序头，降低首轮算力成本。Assembly101 的官方 TSM 为 2048 维，CrossTask 为 3200 维，都不符合现有 74 维骨架入口，需要独立特征投影和标签头。

局部动作可先用几秒级窗口；完整 SOP 往往跨数十秒到数分钟，应再增加事件级序列模型或具有显式状态的流程核对器。现有 6.4 秒窗口不应被当作完整 SOP 上下文。

MECCANO 可支持螺丝相关交互分支。开始训练前核实其数据许可和帧号口径；如使用原有片段分类协议就按原协议报告，若改造成多标签连续检测则单独说明任务变化。

### 第三步：验证流程错误，随后做灯具迁移

IndustReal 文件服务恢复后，按官方协议验证步骤完成与错误执行。Assembly101 错误标注可以先用于序列结构、词表和数据加载研究；只拿真实动作标签预测错误属于“真值事件输入”实验，不能当作端到端视频错误检测结果。

对于现场流程，保留观测到的动作事件，再与正式 SOP 偏序约束比较。不要先强行把模型输出修正成唯一合法顺序，否则会隐藏本来要检测的错序。数据中没有标注到某一步，也不能直接解释成漏做。

灯具迁移优先补采工位 5 的接端子／八颗螺丝，以及工位 6 的吹净／连接动作，记录产品周期、目标位置、可观测性和完成依据。公共数据提供表征与验证方法；端子锁止、螺丝扭矩、实际吹气等完成证据仍依赖现场定义与必要的设备记录。

## 5. 统一数据格式及评测口径

建议分别保存三个表，避免动作、完成点和错误类型混成一个标签：
