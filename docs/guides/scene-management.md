# 模型与场景任务管理

2026-11-06 增加目录批量读取、页面分页、模型加载限流和发布并发检查，详见 [管理性能与服务器部署](management-performance.md)。场景规则、人物计数边界和权重复用优化见 [验证记录](../history/scene-logic-performance-2026-11-06.md)。

后台入口：`http://127.0.0.1:8000/admin`（也支持 `/admin.html`）。首页右上角提供“模型与任务管理”入口，后台与检测首页共用登录会话。本机账户配置位于 `.runtime/local-settings.json`。

## 配置一个新场景

1. 打开后台的“模型库”，点击“导入模型”。默认从**当前浏览器电脑**选择 `.pt` 并上传到服务器；若文件已在服务器，可切换“选择服务器文件”，从 `models/`、`outputs/` 或 `DATA_DIR/model-imports/` 选择。客户端路径不会被当成服务器路径。
2. 填写模型名称、版本和可选说明。页面展示服务器大小限制与传输/验证阶段。系统读取模型任务类型、类别，保存独立权重副本与 SHA-256。成功页可以查看对应模型、创建检测任务，或将支持后台训练的模型带入训练页。
3. 点击“创建任务”，填写场景名称、说明和关联模型。
4. 添加规则，选择类别、判定方式、置信阈值和数量。每条规则可以配置独立的归一化区域，也可选择参考图后点击“图上框选”。参考图仅在浏览器内用于标定，不上传服务器。
5. 调整输入尺寸、设备、采样率、连续确认帧数及最低清晰度。选择“保存草稿”可继续编辑；选择“发布到检测工作台”后，任务进入首页下拉列表。
6. 从 `http://127.0.0.1:8000/` 的“检测任务”选择已发布任务，或在后台点击“进入检测”。始终使用原检测主界面的画面、结果、流程和时间轴，按任务加载对应模型与规则；上传视频或开启摄像头即可开始。旧 `/?scene=任务ID` 链接兼容进入同一主界面。

例如，一个包装模型包含 `product`、`label` 和 `damage` 类别时，可以设置：整幅画面至少检出一个产品；标签区域至少检出一个标签；产品区域禁止出现损坏类别。不同工位可以复制任务，再调整区域、阈值和关联模型。

## 模型与规则边界

服务器导入、共享存储、超时限制和断线恢复说明见 [模型导入部署说明](model-import-server.md)。

- 当前后台接入 Ultralytics `.pt` 检测、实例分割、关键点、旋转框、图像分类模型。特征分类 `.joblib`、任意框架权重和通用动作顺序模型不属于这个运行适配器。
- 每个场景关联一个模型，最多 32 条规则。分类模型每个区域输出一个类别，数量为 1；检测模型可以配置数量范围。
- 区域坐标是 `[x1, y1, x2, y2]`，取值 0–1。推理使用区域裁切，结果映射回整幅画面；更换相机位置后需重新标定。
- “必须检出”：达到最低数量且不超过最高数量，连续证据确认后通过。数量不足、遮挡、模糊或区域像素不足保持“待复核”。
- “禁止出现”：任意一个达到阈值的禁用目标经连续确认后判异常。恢复为未检出也需要相同的连续确认；过渡帧为“待复核”。未检出禁用目标只表示当前无该类证据；发布任务仍须至少一条“必须检出”规则。
- 规则结果缺项、重复或无效时不能通过；推理失败会清除该流的旧判定与待确认帧，重新积累有效证据后才可通过。发布时拒绝同区域同类的检出/禁止冲突、同阈值下不相交的数量范围，以及分类模型同一区域必须属于两个类别的配置；草稿可以暂存这类冲突继续修改。
- 人员规则统计每个区域内可靠检出的人体框，不等于员工身份、跨帧人数去重或动作归属。区域裁切可能截断靠近边缘的人体；两个重叠区域也可能分别计入同一个人。配置工位范围时使用参考图，验收时包含多人、遮挡、跨边界和无人画面。
- 画面最多展示300个去重目标；各区域规则仍使用该区域模型返回的全部目标。单区域模型结果达到300个上限时，不能证明“数量合规”或“禁用目标不存在”，返回待复核；已检出的超量或禁用目标仍可确认异常。
- 模型类别来自训练结果，后台不能凭新增文字让模型识别新类别。更换新类别需导入对应训练权重。
- 结果仅反映所配置的视觉规则，不能替代安装扭矩、胶粘强度或完整工艺顺序验证。

## 检测、历史和版本

视频提交进入现有 Worker 队列，支持进度查询、取消、回放、采样目标、逐项规则与 HTML 报告。实际采样率取任务设置和视频帧率的较小值。历史按场景隔离；重新打开历史会使用该记录的模型、规则与版本。

编辑场景会递增任务版本，不会修改已经提交的视频任务。编辑冲突会提示刷新，防止覆盖另一窗口的修改。停用模型后，关联场景不能接受新检测；已提交视频仍使用其快照。

创建场景的请求支持 UUID 格式的 `Idempotency-Key`。同一账户以相同编号、相同规范化配置重试时返回已有任务；更改配置或已编辑原任务后复用编号会返回409。编辑仍使用 revision 检查。页面对同一次创建的重试保留编号，关闭后重新新建会生成新的编号。

摄像头使用浏览器视频流，将采样 JPEG 交给真实模型推理；每轮隔离证据、时间戳和模型配置。后台改动任务或停用模型后，该摄像头轮次会停止并提示重新开始。结果过期后清除检测框与旧判定；退出或会话失效后停止摄像头。摄像头轮次仅保留当前会话结果，不写入视频历史。

浏览器摄像头需要本机地址或 HTTPS。服务器模型计算要求 CUDA GPU；GPU不可用时明确报错，自动设备选项也不会回退CPU。

## 启动与验证

已有本机服务可双击项目“启动本机服务.cmd”重启。命令行执行 `npm run dev:local` 可在端口空闲时启动 API 和 Worker。已有数据库通过 `backend.init_db` 增加模型库与场景表，保留原任务和媒体记录。注册权重位于 `DATA_DIR/registered-models/`，备份时应连同数据库一起保存；API 与 Worker 必须能读取相同的数据目录路径。

Docker API 镜像已包含新增页面资源；更新部署时重建 API 和 Worker 镜像并执行数据库初始化。

```powershell
npm run test:management
npm run test:management-ui
```

接口与算法测试覆盖权限、发布校验、版本快照、模型停用、五类模型输出、证据确认、流隔离、模型上传失败清理和低帧率视频产物。

浏览器测试会启动独立数据库、API 和 Worker，使用项目真实螺丝模型及参考图验证：模型导入和上传、框选区域、草稿发布、启停模型、首页选择、真实视频分析、回放、历史版本、报告、手机布局和摄像头接口。摄像头输入是浏览器模拟视频源。测试进程结束后关闭，记录与截图保存在 `.runtime/scene-browser-*/`，不向日常模型库写入测试任务。该测试依赖本机 Edge 与 Playwright。


## 管理页面使用提示（2026-11-04）

- 顶部概况显示模型资产、已发布任务、待配置草稿和需要关注的任务；点击数字卡片可进入对应列表。“需要关注”只包含已发布但模型不可用的任务。
- 场景任务支持按名称、描述、模型版本和规则名称搜索，并与发布状态筛选组合使用；可按最近更新、名称或规则数量排序。模型库支持名称、版本、类别搜索及状态、类型筛选。
- 在任务编辑器中，点击模型类别可快速添加规则，也可复制已有规则后调整区域和数量。发布前会检查必需规则、类别、置信阈值、数量范围和检测区域。
- 切换关联模型需要确认，并清空原模型规则后按新类别重新配置；不会按相同类别编号自动继承旧规则。任务名称、说明与运行参数保留。
- 关闭有未保存修改的任务编辑器、停用关联已发布任务的模型、将已发布任务转为草稿时，都会说明影响并要求确认。保存和导入期间会锁定相关表单，防止重复提交或误改。
- 服务器文件列表为空或读取失败时，仍可从当前电脑上传；隐藏的来源不参与表单校验。保存后自动清除任务搜索与筛选，方便找到刚保存的场景。

管理页面的目录筛选与规则校验回归：`npm run test:admin`；后端管理与场景运行回归：`npm run test:management`。页面交互验证应使用独立测试数据，避免向日常模型库写入示例任务。
