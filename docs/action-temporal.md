# 动作时序解码

当前使用 `causal-duration-v3`：按同一人员轨迹、真实时间戳在线累计动作证据，供实时摄像头和新的视频分析任务共用。这是姿态规则的时序解码器，未训练新的神经网络模型；测试通过不代表现场动作准确率已提高。

- 动作确认要求当前证据与指数平滑分数均达到 0.6，累计有效时间至少 0.3 秒，且至少两次观测。5–30 fps 使用同一时间标准，确认时刻允许一个采样周期的离散误差。
- 候选动作短暂降分可保留进度至 0.12 秒；降分区间和恢复的首个区间不累计持续时间。缺失证据立即清空候选进度。
- 已确认动作使用 0.12 的分差滞回，减少相近动作互换；分数持续低于 0.5 达 0.18 秒则退出，低于 0.35 立即退出。旧平滑分数不能单独重新确认动作。
- 关键点不足、轨迹关联不确定、漏检、超过 0.75 秒的解码间隔均中断证据累计。漏检后可继续关联原轨迹编号，但不能继承动作累计时间。
- 重复步骤要求上一动作有明确的低分观测，低于工作流阈值减 0.15 并达到释放时长。空信号、遮挡和离开 ROI 本身不能证明动作已经释放；等待释放时也检查步骤超时。

`temporal.candidateSeconds` 表示候选动作累计的有效支持时长，不包含暂时低证据区间；不再等同于从候选首次出现到现在的墙钟时长。原始关键点保存在 `rawKeypoints`，显示和姿态规则使用轨迹内平滑后的 `keypoints`。

验证：`node tools/python.cjs -m pytest tests/test_action_sequence.py tests/test_algorithms.py tests/test_realtime.py tests/test_lab.py -q`。覆盖多帧率、短暂与持续降分、陈旧分数、漏检重置、非法输入、重复动作、多人隔离与流隔离。需要带人工动作标注的现场视频，才能进一步测量动作 F1、边界延迟和错误切换率。
